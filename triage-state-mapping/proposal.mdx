## 為什麼是現在

三個衝突，全部是現在進行式：

1. `triage` playbook 已安裝，卻沒有 `docs/agents/triage-labels.md`；而 `WORKFLOW.md` 與 `docs/agents/issue-tracker.md` 都禁止發明標籤分類——那正是安裝它所必須做的事。
2. `WORKFLOW.md` 說 G1 是 Discuss 的出口、武裝發生在 G1 之後並把票移到 Todo，又說 gate 等待時狀態是 In Review。照字面讀，一張票會走 In Review → Todo → 再回 In Review。
3. 沒有任何條文涵蓋「無人值守的 run 開跑之後才需要開發者」這件事，而 `retro` 已安裝，契約裡卻沒有一處說明何時該跑。

## 本次 Change 的邊界

- 撰寫 `docs/agents/triage-labels.md`，採三欄——角色、載體、值——因為 vendor 範本的兩欄假設每個角色都是標籤。
- 改寫 `WORKFLOW.md` 與 `docs/agents/issue-tracker.md` 中「不發明標籤分類」的措辭，使其允許 playbook 的 canonical 角色、且僅止於此；兩份檔案中的 `agent:ready` 一律更名為 `ready-for-agent`。
- 把 `WORKFLOW.md` 狀態表中那一列 gate 拆成 G1（Todo）與 G2（In Review）兩列，並寫入執行中換標籤的做法。
- 在 `scripts/check-workflow.js` 加一條 assignee 規則：Backlog 以外的票必須有 assignee。
- 在 `WORKFLOW.md` 加入 `retro` 步驟：merge 之後，若任一 gate 曾被退回或 code review 超過三輪，執行一次 retro，採用的建議開成 issue。
- **不在範圍內，改以母票上的 runbook 處理** —— Linear 的標籤更名與退役、runtime 的 `required_labels` 與 `active_states` 設定、註冊 agent 身分、驗證 tracker 是否會為 agent 的寫入發出通知、驗證 adapter 是否把 blocking edge 算成不可派工、清掉 Codex 那張票的殘留標籤。這些都沒有 diff，也沒有 acceptance scenario。
- **不在範圍內** —— 封存在 `docs/changes/archive/` 的 spec 快照。它們是歷史。

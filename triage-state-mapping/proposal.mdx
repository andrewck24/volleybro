<TLDR>
已安裝的 triage playbook 需要一套 tracker 對照，而交付契約明文禁止——兩者必有一個要讓步。狀態承載粗粒度的進度，標籤承載球在誰手上，blocked 維持用依賴關係表達；`docs/agents/triage-labels.md` 以三欄記下這套對照。G1 改在 Todo 等待，In Review 只代表 G2；執行中卡住的 run 換標籤而不動狀態。開發者擁有的動作是決定而不是按鍵：開發者明確同意後 agent 可代為執行。retro 在契約裡取得觸發條件。
</TLDR>

本頁依 ADR-0060 撰寫：內容逐字取自 G1 確認的最終摘要。

## 範圍

1. 新增 `docs/agents/triage-labels.md`，採三欄對照：角色、載體、值。
2. `WORKFLOW.md` 與 `docs/agents/issue-tracker.md`：放寬「不發明標籤分類」的措辭，只允許 playbook 的 canonical 角色；`agent:ready` 全部改名為 `ready-for-agent`。
3. `WORKFLOW.md` 狀態表：G1（Todo）和 G2（In Review）拆成兩列，並寫入執行中換 label 的做法；「手動接手」那一列和 Manual workflow 一節改成放寬規則。
4. `WORKFLOW.md` 的武裝段落、label／狀態對照表的 Owner 欄、Manual workflow 一節，以及 `issue-tracker.md` 的武裝規則，改寫成「開發者決定，同意後 agent 可代為執行」。
5. `WORKFLOW.md` 新增 retro 步驟：merge 之後，若任一 gate 被退回過，或 code review 超過三輪，就跑一次 retro，採用的建議開成 issue。
6. 不在範圍內，改由母票上的 runbook 處理：Linear 的 label 改名與退役、runtime 的 `required_labels` 和 `active_states`、agent 身分、通知驗證、blocking edge 驗證、清掉殘留的 label，以及 assignee 規則。
7. 不在範圍內：`docs/changes/archive/` 裡的歷史快照。

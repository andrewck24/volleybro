<TLDR>
triage playbook 的七個角色現在有了 tracker 對照：`docs/agents/triage-labels.md` 以角色、載體、值三欄記錄，交付契約只允許這些 label。`WORKFLOW.md` 的狀態表拆成八列，G1 在 Todo、G2 在 In Review，卡住的 run 換 label 不動狀態。開發者擁有的動作改為「開發者決定，經明確同意可由 agent 執行」，未武裝的 issue 由 agent 直接接手。合併後加入 retro 觸發條件。實作沒有偏離 Proposal；review 抓到「派工只看 Todo」與「在 In Progress 重新武裝」互相矛盾，已改為派工看 active status。
</TLDR>

## 留給 G2 的問題

狀態表中「Developer takes an unarmed Change」一列寫的是 `ready-for-human` removed, if present。Proposal 只說 agent 把 issue 移到 In Progress，沒有提到 label。之所以移除，是因為 G1 通過後的 issue 身上帶著 `ready-for-human`，留著的話，在 In Progress 上會被讀成「run 卡住、等開發者」。規格審查把它列為 Proposal 沒要求的規則。請確認要保留，還是改成不動 label。

## 殘留風險

Linear 的 label 已在 G2 前改名與退役：`agent:ready` 改為 `ready-for-agent`、`Bug` 改為 `bug`、`Improvement` 改為 `enhancement`，新增 `needs-triage`、`needs-info`、`ready-for-human`，退役 `Feature` 與 `needs-user`；原本帶 `needs-user` 的兩張 issue 已改貼。剩下三項只在 Symphony 實際派工時才會出問題。

<AfterRelease>

以下是本批合併後，不是現在要操作的步驟：

1. Agent 確認新 controller 已在 main，再由已授權 owner 使用 fresh `normal-retry`，指定原 release PR／application SHA；不 rerun 或批准舊 controller 的 run。
2. 腳本重用完整 Git tree 相同的可信功能證據。缺 scope 就停止 release，由 owner 在同一 trusted main revision 執行 `gh workflow run ci.yml --ref main -f source=<application-SHA>`，等 Test／Integration 通過後 fresh retry；production-release 不重跑功能測試。只有具體 OAuth／browser 缺口才建立固定 integration Preview，並請你驗收該缺口。
3. 腳本查 candidate READY／project／source／production 設定／protection／baseline，彙整已審查的 recovery evidence；你核准 protected candidate gate，不在 random candidate URL 登入 Google。
4. 鎖內重查證據與 baseline 後 promote，脚本執行公開 health check。你在正式網址做 Google／session／team 短 smoke，核准 production gate；通過才 finalize exact-SHA tag／Release。
5. 明確 QA 失敗依已接受相容證據復原；若 run 等待或取消，由 owner dispatch `recover` 指定原 run。Artifact 過期、證據不符或 alias 已改時停止，不憑空授權 rollback、不還原資料。

新增 coverage 的用途是阻止錯 source／producer、錯或缺 receipt、過期／錯 provenance artifact 與 stale alias；primary owner 是公開 controller CLI。未增加 app 測試，不編造節省時間或 tokens 的數字。

### 平台與工具限制

GitHub 原生 `cache-mode: read` 以 scoped cache token 禁止 CI test jobs 寫入 cache，不只略過 cache action。CI source 補證据沒有 app secrets 或 protected deployment environment。參考 [GitHub workflow cache-mode](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#cache-mode)。本輪 CodeQL／獨立審查與最終 gate 尚在重驗；未通過前不宣稱 merge-ready、不 dismiss alert。

Workflow 使用 GitHub 原生 concurrency `queue: max` 保留排隊、不取消既有 production mutation。現有 actionlint 版本尚不認識此欄位，因此完整 actionlint 有該欄位診斷，不能稱為全綠；其他診斷未見。Repository executable checks 與兩軸審查已通過。參考 [GitHub concurrency 文件](https://docs.github.com/en/actions/using-jobs/using-concurrency)。

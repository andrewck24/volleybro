## Scope

單張 PR 的後續安全契約 Change，不改寫 `release-train` 與 `release-owner-hotfix` 已接受歷史。這裡只交付 tooling；部署驗收與發布仍在合併後的 protected gates 完成。

1. 更新 `WORKFLOW.md`、`docs/release-runbook.md`、delivery-workflow Feature 的分層 QA、normal／normal-retry／hotfix 共用規則。保留人類 OAuth 驗收與發布授權，不自動派 Agent 或自批 environment。
2. 在 `production-release.yml` 與 `release-controls.js` 重用既有 state／accepted artifact。先完成現有 normal／normal-retry／hotfix 授權，再以受信任 controller 在 `integration` environment 準備該 exact source 的 Preview，使用既有固定 integration hostname 的 OAuth 設定；絕不為未知 SHA 執行帶 credential 的建置。核對 READY／project／target／source，記錄驗收 deployment、證據網址與 run。Alias 操作重用 native API 與 Preview 共用鎖，拒絕正式 domain；固定 alias 移到不同部署時，原驗收不能直接放行，hotfix 不得借用 integration tip 結果。`integration-preview.yml` 納入影響清點，只調整必要的共用鎖／驗收協作，不放寬 main-only 自動部署。每次 release 可能多一次 Preview build，換取可重複的同 SHA 登入驗收。
3. Promote 前要求本次 baseline／candidate／source 的已接受復原證據。Agent 比較 schema、index、migration、讀寫格式與 deployment 設定；必要時以隔離資料證明新寫入仍可被 baseline 使用。缺證據／不相容停止，另行決定向前修復，不以未定義的人工復原放行。
4. Candidate 保留 Standard Protection；promote 前只以 Vercel API 查 READY／identity／設定／domain baseline，不要求未登入 HTTP，也不新增 protection bypass。首次 production public HTTP smoke 在 promote 後執行；失敗或正式站 QA 明確拒絕沿用相容 rollback／baseline lock。
5. 等待或取消不宣稱會自動復原。`production-release.yml` 新增 owner-only `recover` dispatch，輸入原 release run ID，由 trusted main controller 讀取同 repository、原 production-release workflow 的已接受 artifact；不接受任意 baseline／SHA 替代證據。核對原授權與 reviewer receipt、artifact provenance、project／baseline／candidate／source／原 run 綁定，並驗證本次 actor／rerun actor／trusted main。在共用 production lock 下重查 live alias 仍是原 candidate 才 rollback，完成公開 health check 並通知；不建立成功 tag、不重新發布。Artifact 已過期、缺失、未驗收或 alias 改動全部停止，另行決定復原方式，不降低驗證。這是 cancellation／長時間 pending 的具體人工入口，不是逾時自動化；沿用既有 artifact retention，run summary 說明其到期限制。OAuth／共享設定故障不能只憑 DB 相容就聲稱 code rollback 能修好。
6. 依 test-audit 延伸既有公開 CLI／workflow contract proof：錯 SHA／環境、缺少或跨 run receipt、recover 非 owner／原 run provenance 錯誤／artifact 過期、未驗收不得 finalize。重用 fixture，不新增 auth bypass、新 DB、OAuth proxy 或 test-only export。

不修改 app auth 或資料模型、不切 `production` DB、不 reset 共享 `test`、不處理 Dependabot／landing、不刪 dev。Controller-only 修正不新增 app Changeset。新 controller 經 G2／合併後，以 fresh run 重驗原 release SHA；不直接核准目前舊 run。

### 本次發布的 DB 證據缺口

Baseline 與 release source 初查未見 schema／index 新格式，但 lineup create 與 player removal 的寫入有變動。null 與 ObjectId 格式原已支援，仍不能只憑 candidate 自己的 integration tests 認證跨版本 rollback。Apply 要檢查 baseline fixture → candidate read/write → baseline read/write；對部分失敗與既有異常資料明確區分可證明、未證明項目。部署 rollback 不會還原已刪除的 player reference。現有 migration 工具已退役，不代表共享 DB 資料已全數合規；不因此重建腳本或寫入 DB。

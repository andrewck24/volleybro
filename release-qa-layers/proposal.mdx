## Scope

單張 PR 的後續安全契約 Change，不改寫 `release-train` 與 `release-owner-hotfix` 已接受歷史。這裡只交付 tooling；部署驗收與發布仍在合併後的 protected gates 完成。

1. 更新 `WORKFLOW.md`、`docs/release-runbook.md`、delivery-workflow Feature 的分層 QA、normal／normal-retry／hotfix 共用規則。保留必要發布授權與目前尚無安全自動 proof 的正式 Google／session／team 短 smoke；不固定新增人工 Preview 功能 gate，不自動派 Agent 或自批 environment。已由可信自動證據涵蓋的功能不再人工驗收；完整 authenticated automation 仍由既有後續工作擁有，本次不假裝已實作。
2. 在 `production-release.yml` 與 `release-controls.js` 重用既有 state／accepted artifact，先完成 normal／normal-retry／hotfix 授權，以 source／驗證範圍／可信 producer／成功結果核對並重用現有 CI 與驗收證據；不同 SHA 不默默算成同一結果。Source 功能證據充分時，不額外建 Preview、不派 Agent。只有具體缺口才在 `integration` environment 準備 exact source Preview，使用固定 integration hostname 的 OAuth 設定，不為未知 SHA 執行帶 credential 的建置。核對 READY／project／target／source，記錄 automated 或必要 manual receipt 與 run；alias 操作重用 native API／Preview 共用鎖、拒絕正式 domain。Alias 移動不得沿用不符部署的驗收，hotfix 不借用 integration tip。`integration-preview.yml` 只調整必要共用鎖／驗收協作，不放寬 main-only 自動部署；extra Preview build 只發生在缺口分支。
3. Promote 前由腳本彙整並綁定已審查的復原證據到 baseline／candidate／source／run，沿用人工發布 approval，不要求開發者重讀既有測試。先重用交付時的 schema／index／migration／讀寫格式判定與 integration 結果；單靠路徑未變或測試綠燈不自動宣告相容。只有持久化 contract 改變或證據不確定時才請 Agent 分析，只有「有具體新格式風險且承諾退回該舊版」才補最小跨版本 integration cases。未知／不相容不授權 rollback，也不以未定義的人工復原放行；需另定向前修復策略。Deployment 設定與 live baseline 仍由 API read-back 機械查證，不能被本機測試替代。
4. Candidate 保留 Standard Protection；promote 前只以 Vercel API 查 READY／identity／設定／domain baseline，不要求未登入 HTTP，也不新增 protection bypass。首次 production public HTTP smoke 在 promote 後執行；失敗或正式站 QA 明確拒絕沿用相容 rollback／baseline lock。
5. 等待或取消不宣稱會自動復原。`production-release.yml` 新增 owner-only `recover` dispatch，輸入原 release run ID，由 trusted main controller 讀取同 repository、原 production-release workflow 的已接受 artifact；不接受任意 baseline／SHA 替代證據。核對原授權與 reviewer receipt、artifact provenance、project／baseline／candidate／source／原 run 綁定，並驗證本次 actor／rerun actor／trusted main。在共用 production lock 下重查 live alias 仍是原 candidate 才 rollback，完成公開 health check 並通知；不建立成功 tag、不重新發布。Artifact 已過期、缺失、未驗收或 alias 改動全部停止，另行決定復原方式，不降低驗證。這是 cancellation／長時間 pending 的具體人工入口，不是逾時自動化；沿用既有 artifact retention，run summary 說明其到期限制。OAuth／共享設定故障不能只憑 DB 相容就聲稱 code rollback 能修好。
6. 依 test-audit 先清點既有 proof，再只補真實缺口：錯 SHA／環境、缺少或跨 run receipt、recover 非 owner／原 run provenance 錯誤／artifact 過期、未驗收不得 finalize。每項新增／修改測試說明可觀察 contract、可信 regression、既有 coverage 為何不足與 owning tier；優先延伸既有 case／fixture，不重複 unit／integration／E2E 同一斷言，不加 source-string 自證或 test-only seam。跨版本測試在對應 rollback 目標退役後可移除，保留發布證據；新版讀舊格式的測試則等舊資料格式退役後再移除。G2 列出剩餘人工動作與頻率、Agent 介入條件、機械證據 owner 及每項新測試的用途，不編造節省數字。

不修改 app auth 或資料模型、不切 `production` DB、不 reset 共享 `test`、不處理 Dependabot／landing、不刪 dev。Controller-only 修正不新增 app Changeset。新 controller 經 G2／合併後，以 fresh run 重驗原 release SHA；不直接核准目前舊 run。

### 驗證 owner 與成本邊界

| 要證明的事 | 主要 owner | Release 不重複做的事 |
| --- | --- | --- |
| 計算、validation、mapping／狀態 | 現有 unit tests | 不人工重演；不搬同一斷言到其他 tier |
| Repository／constraint／transaction／legacy data | 現有 integration tests | 不固定人工查 DB；不為每次發布建立跨版本套件 |
| 必要的頁面串接／瀏覽器行為 | 已存在且安全的 E2E；缺口才 targeted QA | 不以預建 session 宣稱真實 Google OAuth 通過；不於本次新建完整 E2E 系統 |
| Deployment identity／config／protection／baseline | 現有 API／controller 腳本 | 不請人或 Agent 手動逐項讀平台設定 |
| 正式 Google／session／team 短 smoke | 尚未自動化的必要人工 fallback | 不重做全部 app 功能；有可信替代 proof 後再退役人工作業 |

這次發布未見 schema／index 新格式；lineup 的 ObjectId／null 原已支援，寫入修正已有 integration coverage，沒有已識別的新格式風險要求常駐跨版本測試。保留 diff 判定與既有 proof，不固定執行 baseline → candidate → baseline。這不是全部復原條件已通過：code rollback 不還原已刪 player reference，部署設定／共享狀態仍需相符證據；不連共享 DB、不重建 migration 工具。

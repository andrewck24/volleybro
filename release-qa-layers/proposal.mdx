## Scope

單張 PR 的後續安全契約 Change，不改寫 `release-train` 與 `release-owner-hotfix` 已接受歷史。這裡只交付 tooling；部署驗收與發布仍在合併後的 protected gates 完成。

1. 更新 `WORKFLOW.md`、`docs/release-runbook.md`、delivery-workflow Feature 的分層 QA、normal／normal-retry／hotfix 共用規則。保留人類 OAuth 驗收與發布授權，不自動派 Agent 或自批 environment。
2. 在 `production-release.yml` 與 `release-controls.js` 重用既有 state／accepted artifact。核對 Preview 的 READY／project／target／exact source，記錄驗收 deployment、證據網址與 run。固定 integration alias 移到不同部署時，原驗收不能直接放行；hotfix 也不得借用 integration tip 的結果。
3. Promote 前要求本次 baseline／candidate／source 的已接受復原證據。Agent 比較 schema、index、migration、讀寫格式與 deployment 設定；必要時以隔離資料證明新寫入仍可被 baseline 使用。缺證據／不相容停止，另行決定向前修復，不以未定義的人工復原放行。
4. 公開 smoke 或正式站 QA 明確失敗沿用相容 rollback／baseline lock。等待或取消不宣稱會自動復原；summary 與 runbook 列出 owner 復原入口。OAuth／共享設定失敗不能只憑 DB 相容就聲稱退回程式能修好。
5. 依 test-audit 延伸既有公開 CLI／workflow contract proof：錯 SHA／環境、缺少或跨 run receipt、未驗收不得 finalize。重用 fixture，不新增 auth bypass、新 DB、OAuth proxy 或 test-only export。

不修改 app auth 或資料模型、不切 `production` DB、不 reset 共享 `test`、不處理 Dependabot／landing、不刪 dev。Controller-only 修正不新增 app Changeset。新 controller 經 G2／合併後，以 fresh run 重驗原 release SHA；不直接核准目前舊 run。

### 本次發布的 DB 證據缺口

Baseline 與 release source 初查未見 schema／index 新格式，但 lineup create 與 player removal 的寫入有變動。null 與 ObjectId 格式原已支援，仍不能只凭 candidate 自己的 integration tests 認證跨版本 rollback。Apply 要檢查 baseline fixture → candidate read/write → baseline read/write；對部分失敗與既有異常資料明確區分可證明、未證明項目。部署 rollback 不會還原已刪除的 player reference。現有 migration 工具已退役，不代表共享 DB 資料已全數合規；不因此重建腳本或寫入 DB。

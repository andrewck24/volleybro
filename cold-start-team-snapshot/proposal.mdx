## 範圍

1. **存什麼、用在哪：** 最後一次的 active `teamId` 與該球隊的 `TeamView`。冷啟動時作為 `useActiveTeamId` 與 `useTeam` 的初始值，之後照常重新驗證。只有這兩個 hook 改變，所有使用 `useActiveTeamId` 的元件不必改。
2. **身分綁定：** 快照帶 `userId`；`useUser` 回來後不符就丟棄並清除；登出時清除。
3. **兩層：** interface 層是 `TeamSnapshotStorage` 型別（`load`、`save`、`clear`）與 hook 端的使用，放在 `src/lib/features/team/`；persistence 層是 localStorage 實作，獨立成一個檔案，是唯一碰 `localStorage` 的地方，可注入以利測試，版本號放在快照內，做法照 `pending-writes-storage` 的先例。
4. **寫入時機與過期：** 每次 `useTeam`、`useActiveTeamId` 成功後覆寫；不設 TTL，因為每次掛載都會重新驗證，正確性從不靠快照。
5. **儲存失敗：** 私密模式、容量已滿、資料損壞一律當作沒有快照，退回現在的行為。這與 `pending-writes` 不同：那是不能丟資料的佇列，所以不吞錯；這裡只是快取，可以吞。

**不在範圍內：** 球員名單、比賽列表等其他資料的快取；service worker 的快取策略；新增比賽表單既有的預設隊名衍生邏輯（冷啟動沒有快照的第一次使用仍走那條路）。

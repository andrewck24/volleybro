### Layout Specifications

根據 Epic 1.11 規格：

**TeamManagementSection 內容設計**：

1. **卡片 1 - 建立完整隊伍名單**：
   - 標題：「建立完整隊伍名單」
   - 描述：輕鬆建立和管理球員資料，掌握每位成員的基本資訊和比賽表現
   - 展示：球員名單管理界面或成員資料卡片
   - 重點：成員管理、資料建檔、聯絡管理

2. **卡片 2 - 智慧陣容安排**：
   - 標題：「智慧陣容安排」
   - 描述：根據球員能力與狀況，快速安排最適合的先發陣容
   - 展示：陣容配置界面或位置安排視覺化
   - 重點：戰術配置、位置安排、陣容優化

**佈局控制**：

- TeamManagementSection: 兩個卡片都使用圖右文左佈局（`lg:flex-row`）
- 與 RecordingSection 保持一致的佈局方向
- 卡片高度：`lg:h-[70vh]`，展示區域 1:1 比例漸層背景
- 響應式：行動裝置自動切換為圖上文下垂直佈局（`flex-col`）

### Design System Integration

**[Source: architecture/coding-standards.md#tailwind-css-conventions]**

Tailwind CSS 最佳實踐：

- 使用設計系統代幣（bg-card、text-card-foreground）
- 邏輯類別分組（佈局、間距、顏色、排版）
- 行動優先響應式設計（mobile-first）

```tsx
// TeamManagementSection 佈局控制 - 圖右文左
<FeatureCard
  layout="right-image" // 對應 lg:flex-row
  className="flex w-full flex-col items-center justify-center gap-6 lg:h-[70vh] lg:gap-8"
  gradientClass="bg-gradient-to-br from-orange-500/10 to-red-500/10"
>
```

### Component Reusability Patterns

**[Source: architecture/coding-standards.md#react-component-standards]**

FeatureCard 介面已定義：

```typescript
interface FeatureCardProps {
  title: string;
  description: string;
  className?: string;
  gradientClass: string;
  children: React.ReactNode;
  testId: string;
  demoTestId: string;
  layout: "left-image" | "right-image";
}
```

- `layout: "right-image"` 對應 `lg:flex-row`（圖右文左）
- `layout: "left-image"` 對應 `lg:flex-row-reverse`（圖左文右）
- 透過 layout 屬性控制圖文佈局方向

### Testing Patterns

**[Source: architecture/coding-standards.md#testing-patterns]**

必須遵循的測試標準：

- 使用 `data-testid` 屬性進行可靠元素選擇
- 優先使用語意查詢（getByRole、getByLabelText）
- 測試使用者互動，非實作細節

測試識別符建議：

```typescript

```

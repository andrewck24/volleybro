## Independent Pre-PR review round 1 · 2026-08-04

The independent review rejected the first candidate because the visible lifecycle was not yet a
validated metadata gate, dated Archive directories changed the apparent Change slug, the
implementation page manually duplicated plan order, and the durable Review retained operational
tracker identifiers. It also identified unrelated staged feature work and landing-image deletions
in the dirty worktree as scope contamination; those files remain outside this Change and were not
staged, reverted, or otherwise modified during the fix round.

The accepted findings were resolved as follows:

- added a validated lifecycle field and made each workflow transition explicit from Discuss through
  Archive;
- kept the metadata slug stable while restricting the date prefix to the Archive directory name;
- made a server-side loader discover and validate every slice, require an exact plan/file ID set,
  verify dependency order, and render in canonical `plan.json` order; and
- removed tracker names, links, and identifiers from the active durable Change while retaining the
  operational adapter only in repository workflow configuration.

Targeted component and contract tests, TypeScript, the 67-page production Blueprint build, and
rendered Implementation and Change catalog checks passed after the fix round. A second independent
review is required before this gate reaches a fixed point.

## Independent Pre-PR review round 2 · 2026-08-04

The second review confirmed the first-round lifecycle, stable-slug, plan-order, tracker-neutrality,
Manual ownership, and Changeset corrections, but rejected the candidate on two remaining retention
boundaries:

- the Implementation loader and route supported only an active `in-progress` Change, so moving the
  complete Change to a dated Archive directory would stop rendering its retained slices; and
- the decision renderer checked only status, schema version, and non-empty targets, leaving the full
  decision-record schema unenforced at runtime.

The fix round made the loader accept validated active or Archive locations, derive the canonical
plan slug from `change.json`, and added an Archive fixture proving a dated directory still loads its
stable-slug plan. It also introduced one comprehensive decision-record parser shared by rendering
and tests, covering allowed fields, IDs, statuses, unique hierarchical targets, required content,
alternatives, optional origin, and rejection of runtime-only fields.

Seven targeted suites with 19 tests, TypeScript, and the 67-page production Blueprint build pass
after these fixes. A third independent review must confirm the fixed point.

## Independent Pre-PR review round 3 · 2026-08-04

The third review confirmed all earlier corrections but found one remaining contract drift in
implementation slices: the runtime parser accepted only two-digit IDs while the schema permits IDs
from two digits upward, and the parser allowed a non-string optional `$schema` value. The fix aligned
the parser and schema across ID shape, optional schema reference, hierarchical capabilities,
non-empty arrays, and uniqueness constraints. Regression coverage now proves `S100` is accepted and
a numeric `$schema` is rejected.

Five focused suites with 17 tests, TypeScript, and the 67-page production Blueprint build pass after
the parity fix. A fourth independent review must confirm the fixed point.

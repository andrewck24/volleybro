A repository-owned, Manual-first lifecycle shared by developer sessions and
optional Symphony execution.

## Current behavior

- Two human gates bound the whole lifecycle: **G1** accepts the Proposal page
  before any implementation starts, **G2** accepts the Review page before
  the pull request opens. Everything between a gate and the next runs without
  stopping for a human.
- Apply decomposes an accepted Proposal into slices — Linear sub-issues under
  the Change's issue, the same way in manual and Symphony mode — unless the
  Change fits one session, which implements directly instead. Either way it
  implements, code-reviews to a fixed point, then runs Archive — all before
  G2, in one pass.
- Archive runs automatically once Pre-PR code review reaches its fixed point,
  before the pull request opens: it promotes behavior and durable constraints
  to Features, exports the Review summary, and stops for G2 acceptance.
  Decision records are not part of that promotion — each already lives at its
  permanent path from the moment it was written.
- Symphony claims a Change once the developer adds `agent:ready` to its
  tracker issue after G1 acceptance, moving it to Todo in the same step.
  Before Manual Apply, the developer checks that no claim exists, removes
  the label, moves the issue to In Progress, and checks again — closing
  the race with a Symphony claim.

## Constraints

- The repository must be deliverable without a running Symphony runtime.
- No pull request opens before Archive completes and the developer accepts
  the Review page (G2); merge performs no second knowledge sync.
- Blueprint's Change review surfaces (`proposal.mdx`, `review.mdx`) are
  gitignored on the Change branch and published to the `blueprint-changes`
  store branch at each gate, which is their durable store — not the Change
  branch itself.
- A small fix that only restores behavior Features already describe, or
  changes no behavior, may skip both gates via the Fix path: no Proposal or
  Review page, only a pull request the developer accepts, carrying a
  `Refs: <tracker issue>` commit trailer instead of `Implements` and
  `Blueprint-Change`.

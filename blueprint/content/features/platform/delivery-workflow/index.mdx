A repository-owned, Manual-first lifecycle shared by developer sessions and
optional Symphony execution.

## Current behavior

- Two human gates bound the whole lifecycle: **G1** accepts the Proposal page
  before any implementation starts, **G2** accepts the Delivery page before
  the pull request opens. Everything between a gate and the next runs without
  stopping for a human.
- Apply decomposes an accepted Proposal into slices in `.scratch/<slug>/`
  (manual) or Linear sub-issues (Symphony), implements them, reviews to a
  fixed point, then runs Archive — all before G2, in one pass.
- Archive runs automatically once Pre-PR review reaches its fixed point,
  before the pull request opens: it promotes ADRs and behavior to Features,
  exports the Delivery summary, and stops for G2 acceptance.
- Symphony claims a Change once the developer moves its tracker issue into
  the ready-to-start status after G1 acceptance. Manual Apply checks that the
  status is absent, and checks again after any developer removal, before
  starting — closing the race with a Symphony claim.

## Constraints

- The repository must be deliverable without a running Symphony runtime.
- No pull request opens before Archive completes and the developer accepts
  the Delivery page (G2); merge performs no second knowledge sync.
- Blueprint's Change review surfaces (`proposal.mdx`, `delivery.mdx`) are
  gitignored and regenerated locally at each gate — they are throwaway review
  surfaces, not durable storage.

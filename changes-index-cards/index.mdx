<TLDR>
`/changes` 在改成兩道 gate 時退化成一串標題連結，沒有日期、狀態，也沒有排序；Blueprint 的 `/` 則只是轉址到 `/changes`，連預覽工具都判斷不出 server 已經啟動。這個 Change 讓兩種格式的 Change 都用 `startedAt` 與 `archivedAt` 標日期，`/changes` 改回卡片、由新到舊排在同一條時間軸上，並替 Blueprint 建一個真正的首頁。
</TLDR>

| | 現在 | 之後 |
| --- | --- | --- |
| `/changes` | 標題連結清單，單頁格式依 slug 排序，舊格式另外排在後面 | 卡片：標題、描述、狀態、日期、capability；兩種格式混排，由新到舊 |
| 單頁格式的日期 | `publishedAt`、`mergedAt`；`mergedAt` 在合併前 publish 後一直是 null | `startedAt`（第一個 commit）、`archivedAt`（落地 `dev`）；合併後重新 publish 一次 |
| `/` | 轉址到 `/changes`，回應 307 | 首頁：簡短介紹與 Features、Changes、Design System 三個入口，回應 200 |

## 範圍

1. `facts.json` 改用 `startedAt` 與 `archivedAt`：`startedAt` 取這個 Change 第一個 commit 的時間，還沒有 commit 時取第一次 publish；`archivedAt` 取代 `mergedAt`。store 分支的 commit 時間曾被整批匯入與 rebase 改寫，所以不採用。
2. `WORKFLOW.md` 合併後的收尾加上一步：從 `dev` 重新 publish 這個 Change，讓 `archivedAt` 寫進 `facts.json`。已合併但還沒有 `archivedAt` 的 Change 在本 Change 內補發。
3. `/changes` 以卡片呈現，兩種格式依 `archivedAt ?? startedAt` 由新到舊排序。
4. Blueprint 首頁 `/`。

還沒完成的舊格式 Change（仍在 proposing 或 discussing）沒有 `archivedAt`，照 `startedAt` 排序。

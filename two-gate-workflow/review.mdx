<TLDR>
The delivery workflow now stops for you twice: the Proposal page before implementation and this Review page before the pull request. Change pages like this one are gitignored on the Change branch and published to the `blueprint-changes` store branch at each gate instead of being committed here. The 22 old Change directories moved to that store branch, the deployed site now carries every published Change alongside Features and the Design System, and the reasoning survives as Feature ADR D45. A third, lighter Fix path also lands in this Change: small corrections skip both gates entirely.
</TLDR>

## What you are accepting

| Area | Before | After |
| --- | --- | --- |
| Human gates | Discuss exit, proposal authorisation, slice-plan approval, per-round code-review updates, delivery acceptance | G1 Proposal page, G2 Review page |
| Change pages | Overview, Design, Implementation, Review, slice JSON, `change.json` lifecycle, all committed | `proposal.mdx` (plus optional `proposal.tsx` mockup) and `review.mdx`, gitignored |
| Slices | Blueprint JSON with status | Linear sub-issues under the Change's issue, manual and Symphony alike; skipped for a one-session Change; closed after Archive; `Implements` trailer stays |
| Handoff in manual runs | Told to the developer only | The pushed branch, its commits, and the sub-issues, so another agent, worktree, or machine can resume |
| ADR status | `candidate` → `accepted` → `implemented` field | Directory says proposed or adopted; `supersededBy` names a replacement |
| Change size | No guidance | Soft targets of 5 slices, 30 src files, 8 scenarios, 40-line PR summary; warnings only; `Migration:` trailer for sharded refactors; structure and behaviour never mixed |
| Deployed Blueprint | Features, Design System, every Change | Features, Design System, every published Change |
| Change page storage | Regenerated locally at each gate, nothing committed | Regenerated locally, published to the `blueprint-changes` store branch at each gate; deploys pull every published Change |
| Arming unattended runs | `agent:ready` label only | Developer adds `agent:ready` and moves the issue to Todo; Symphony takes labelled issues in active statuses; each later status move has one owner |
| Worktree environment | Dummy variables typed at build time | `.worktreeinclude` copies `.env.local` into agent-created worktrees |
| Small fixes | No lightweight route; every fix went through both gates | Fix path: no G1/G2, docs/config/behaviour-restoring fixes only, a pull request with a `Refs:` trailer is the only gate |

<TLDR>
The delivery workflow now stops for you twice: the Proposal page before implementation and this Delivery page before the pull request. Change pages like this one are no longer committed. The 24 old Change directories are gone from the tree, the deployed site shows only Features and the Design System, and the reasoning survives as Feature ADR D45.
</TLDR>

## What you are accepting

| Area | Before | After |
| --- | --- | --- |
| Human gates | Discuss exit, proposal authorisation, slice-plan approval, per-round Review updates, delivery acceptance | G1 Proposal page, G2 Delivery page |
| Change pages | Overview, Design, Implementation, Review, slice JSON, `change.json` lifecycle, all committed | `proposal.mdx` (plus optional `proposal.tsx` mockup) and `delivery.mdx`, gitignored |
| Slices | Blueprint JSON with status | Linear sub-issues under the Change's issue, manual and Symphony alike; skipped for a one-session Change; closed after Archive; `Implements` trailer stays |
| Handoff in manual runs | Told to the developer only | The pushed branch, its commits, and the sub-issues, so another agent, worktree, or machine can resume |
| ADR status | `candidate` → `accepted` → `implemented` field | Directory says proposed or adopted; `supersededBy` names a replacement |
| Change size | No guidance | Soft targets of 5 slices, 30 src files, 8 scenarios, 40-line PR summary; warnings only; `Migration:` trailer for sharded refactors; structure and behaviour never mixed |
| Deployed Blueprint | Features, Design System, every Change | Features and Design System |

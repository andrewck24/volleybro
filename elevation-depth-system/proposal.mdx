由舊格式機械轉換，未經 G1／G2；持久知識見 Features 與決策記錄。

<TLDR>
  建立三層 elevation 模型、overlay depth 規則與一致的
  Dialog、AlertDialog、Drawer 組合。
</TLDR>

## Proposal

## Why

現行色彩系統有一個語意缺陷：light 模式下 `--background`、`--card`、`--popover` 三者同值（98.45%），頁面層與表面層塌陷成一層。為了讓頁面與 card 有對比，body 被迫使用 `bg-accent`——一個語意上屬於 hover/highlight 的 token——而 `docs/design-system.md` 又把這個 workaround 寫成正典，讓漂移固化進設計規則。

這阻斷了一致的 elevation：modal 內的 card 無法與 modal 表面分離，只能靠 per-component hack（在 dialog 內抑制 Card 的 ring/shadow）。另外兩個缺口：`entry-ui` 拿掉 overlay 元件的 ring 之後效果更好，但這個觀察從未被寫成規則；`entry-ui` 新增的 Drawer（vaul bottom sheet）自帶 dimming overlay 卻落在 `bg-card`，舊的 overlay 模型無法解釋。設計語言本身也沒有單一的參考渲染面。

## What Changes

1. **三層背景模型**：`--background`（layer 0，僅頁面本體）、`--popover`（layer 0.5，無 overlay 浮動面）、`--card`（layer 1，Card/Item **＋所有 modal 類**）。body 從 `bg-accent` 改為 `bg-background`；modal 與頁面的分離由 scrim 表達，共用 card 色讓 Drawer peek 與頁面 card 系統全生命週期連續。
2. **容器一律不帶 ring（D5）**：modal/popover/card 都是容器，ring 策略統一為全無；`--ring` 只保留給 focus-visible；同色表面上的 card 類以 shadow 補償。
3. **三段式 overlay shell**：Dialog / AlertDialog / Drawer 共用 Header/Body/Footer 結構（各自持有 padding、Body 是唯一捲動容器）、統一 close/expand 控制群與 `srOnly` prop。AlertDialog 保留明確選擇的 dismiss 語意（Esc 也被阻擋）。
4. **design-system 參考頁**：blueprint 的 design-system section 直接渲染真實 tokens 與規則，取代 `docs/design-system.md` 的過時文字成為 source of truth。
5. **Token 生命週期**：決策期 blueprint 直接 import app 的 token 源（不漂移）；定案後凍結、內聯進各自的 `globals.css`（不留獨立 tokens 檔案）。

## Impact

- 影響 specs：`elevation-tokens`（三層契約 + 圖層歸屬）、`overlay-layout`（三段式結構、no-ring、dismiss 語意、srOnly）
- 影響程式：token blocks（兩側 globals.css）、`dialog.tsx` / `alert-dialog.tsx` / `drawer.tsx` / `popover.tsx` / `select.tsx` / `card.tsx` / `item.tsx` primitives、10+ 個 dialog call sites、`docs/design-system.md`、blueprint design-system section 與本 change 頁
- 測試：新增 dialog / alert-dialog 元件測試（TDD），既有 748 tests 全綠

## 已定案決策

- **D1 — 表面角色決定圖層：** `--background` 是頁面（layer 0），`--popover` 是無 scrim 浮面（layer 0.5），`--card` 是 Card/Item 與 Dialog、AlertDialog、Drawer（layer 1）。Modal 與頁面的分離由 scrim 表達；Drawer peek 和頁面 card 保持同色連續，卡片內部靠 shadow 區分。
- **D2 — 亮度表達高度：** light 由暗到亮為 background 95.6% → popover 約 97% → card 98.45%；dark 反轉為 4.9% → 約 10% → 14.5%。HSL 數值可調，階層順序是契約。
- **D3 — 三段式 overlay shell：** Header、Body、Footer 各自持有 padding；Content 不加 padding並裁切溢出；Body 是唯一捲動區，桌面 scrollbar 貼齊視窗邊緣。
- **D4 — 共用控制群與標題語意：** DialogContent 內建右上角 close/expand 控制群；Title/Description 提供 `srOnly` prop，取代散落的 `sr-only` class 與 `aria-describedby={undefined}`。
- **D5 — 容器不帶裝飾 ring：** Overlay 靠 scrim，Popover 靠背景階差與 `shadow-md`，Card 靠階差與 shadow；`--ring` 僅供 `focus-visible`，同色表面上的 Card 也用 shadow 補償。
- **D6 — AlertDialog 保留明確選擇：** AlertDialog 與 Drawer 使用共用 shell、`bg-card`、無 ring；AlertDialog 不顯示 close/expand 控制，也不允許點外部或按 Esc 關閉，必須明確取消或確認。
- **D7 — Blueprint design-system 是規則的成品與來源：** 直接呈現共用 tokens 與規則，取代過時的 `docs/design-system.md` 文字。

## Lab 說明

<AnchorAliases ids={["overlay-lab"]} />

**Lab A — Overlay：** 以真實記錄畫面的 header、court、panel 與 drawer peek 為底，並排呈現 light/dark；分別切換 Drawer、Dialog、AlertDialog、`bg-background`/`bg-card` 與 ring 開關。預設比較的是已定案的 `bg-card`、無 ring；有 ring 與 `bg-background` 只供反例比較。

<AnchorAliases ids={["ring-lab"]} />

**Lab B — 非 overlay 容器：** 在真實頁面並排比較 Popover（`bg-popover` + shadow）與 Card（`bg-card`）的 light/dark 版本，切換裝飾 ring，確認背景階差與 shadow 足以呈現層級。

<AnchorAliases ids={["drawer-question"]} />

Drawer 使用 `bg-card` 的關鍵理由是 peek 的生命週期連續：Drawer 收合時與頁面 panel/header 同色，展開後仍維持同一表面角色。改用 `bg-background` 雖會讓內部 card 自然浮起，但破壞 peek 與頁面表面的連續性；內部同色元素改由 D5 的 shadow 規則處理。`AlertDialogContent` 因此由 `bg-background` 改為 `bg-card`。

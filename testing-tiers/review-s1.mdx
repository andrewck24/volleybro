<Deviations>

1. **Replica set 在 Jest 的 global setup 啟動，每次執行一個。** ADR-0087 原寫每個測試檔各自啟動。`MongoMemoryReplSet` 在 Jest 的 test environment 中無法完成 driver 初始化 replica set 的 handshake，同樣的程式在一般 Node 中可以，所以改在 global setup 啟動，並讓每個測試檔使用自己的資料庫。整合測試因此從約 85 秒降到約 17 秒。另外兩點調整：mongod 的啟動等待時間放寬到 60 秒，因為 `verify:all` 會與 app build 同時執行；並開啟 test commands，供 failpoint 使用。
2. **8 個 route 測試檔被刪除，而非合併。** 這些檔案只 import `@jest/globals`、測試 helper 與 entity 的 enum，從未 import 它們的 route。它們斷言的是測試自己建出來的值，合併進 `route.test.ts` 不會多證明任何事。另外 5 個 `request-schema.test.ts` 都已逐案改名為 `route.test.ts`。
3. **set 結果寫入失敗的案例從 `api/` 移到 `persistence/`。** 原本在 `api/` 中以 `jest.spyOn` 替換 repository 自己的 `completeSet`，這違反 ADR-0086 的替換界線。現在改由 use case 進入，以 `failCommand` failpoint 讓 `findAndModify` 失敗；entry 寫入走 `bulkWrite`，不受影響。`game-entry-writes` 從 repository 進入，也一併移入 `persistence/`。
4. **`/api/auth/[...all]` 的 route 測試替換了 `better-auth/next-js`。** 這條 route 只有一行，把 app 的 auth instance 交給 Better Auth。S5 要求每條 route 都有測試，而 Better Auth 是 Jest 不轉譯的 ESM，屬於 ADR-0086 所說「環境跑不了的 runtime」，所以測試只證明這層接線。
5. **`.spec` 檔名一律回報，Jest 也只收 `.test`。** ADR-0091 只命名 `.test`。check 原本把 `.spec` 視同 `.test`，review 指出 config、check 與文件三者不一致，現在三者都只認 `.test`。repository 中沒有 `.spec` 檔。
6. **`blueprint:gate` 讀一次預覽 build 的結果，由上一個 Change 完成。** 範圍第 8 點的這一項在 `migration-single-page` 已實作並有測試，本 shard 沒有修改 `scripts/blueprint-gate.js`。
7. **`knip --production` 的位置只記在 ADR-0092。** 文件描述的是現況，不寫將來的計畫；死碼分流完成後，由那個 Change 把它加進 gate。
8. **Testing Feature 在本分支更新。** 這是 Archive 的一步，內容描述本 shard 合併後的現況。
9. **review 走了四輪。** 第二輪起的發現都針對前一輪的修正。註解與決策紀錄重複（根本原因 B）連續兩輪出現後，改用刪除該註解的做法，不再改寫。

</Deviations>

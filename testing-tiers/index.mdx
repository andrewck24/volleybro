<Proposal>

<TLDR>
  整合測試的定義只寫了「從 route 進入」，實際上不少從 repository 或 use case
  進入；repository 單元測試在 stub 過的 driver 上只證明 mock 被傳回，許多元件測試 mock
  了自己的元件與 hook；本機 gate 跑完整文件站 build，卻從不跑整合測試。這個 Migration Change
  以「是否碰到 out-of-process 依賴」重新定義測試分層，把每一層的測試搬到能證明它該證明之事的位置，並讓本機
  gate 只跑 diff 影響得到的檢查。
</TLDR>

|                     | 現在                                                  | 之後                                                                               |
| ------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 一個測試屬於哪一層  | 依目錄與進入點，文件只描述 route 進入                 | 依是否碰到 out-of-process 依賴：unit、integration、end-to-end、API smoke           |
| 整合測試的資料庫    | 單機記憶體 Mongo，沒有 transaction                    | 記憶體 replica set，與正式環境同引擎同拓撲                                         |
| repository 的行為   | 在 stub 過的 driver 上斷言呼叫形狀                    | 在 `persistence/` 對真實資料庫證明；對應與錯誤轉換是純函式單元測試                 |
| 元件測試替換什麼    | 自己的子元件、hook、`apiClient`                       | 只替換網路（MSW）與 jsdom 跑不了的框架 runtime                                     |
| 本機 final gate     | 永遠跑流程工具測試與文件站 build，從不跑整合測試      | 只跑 diff 影響得到的檢查；文件站由 CI 與分支預覽 build，gate 讀一次預覽結果       |

## 範圍

四個 shard 依序進行，每個是各自的 pull request。Shard 1 就是本頁，以本頁的 Review tab 過 G2；Shard 2 到 4 跳過 G1，各以自己的 Change 頁直接到 G2。

### Shard 1：基礎與整合測試整理（`testing-tiers`）

1. 改寫 `docs/testing-strategy.md`，依 ADR-0085 到 ADR-0091 描述四種測試、各自可替換什麼、放在哪裡；end-to-end 與 API smoke 只寫定義。
2. Jest 設定檔除 `jest.config.ts` 外搬進 `test/setup/`；整合測試改用 `MongoMemoryReplSet`。
3. `test/integration/` 分成 `api/` 與 `persistence/`；`api/` 改為只透過 route 與 repository 介面安排、讀回資料。
4. 刪除三個只保護舊資料的測試：讀取帶舊 weather 欄位的比賽、stats 欄位與 entries 不一致的比賽，以及 `team-membership-writes` 中以原始大小寫儲存邀請的案例。`test`
   資料庫中這三種文件都不存在，上線前的資料轉換也不需要它們。
5. `smoke` 只保留「測試之間清空 collection」一案，改名 `test-isolation`；`legacy-entry-guard` 保護的是現行寫入邏輯，改名後移入 `persistence/`。
6. 只斷言 schema 拒絕的整合測試案例移回 route 單元測試；每條 route 的單元測試合併成一個 `route.test.ts`。
7. 新增測試檔名與目錄一致的檢查。
8. `scripts/verify.js` 與 `WORKFLOW.md` 的 section gate、final gate 改依 ADR-0092：整合測試依 diff 跑、流程工具測試依 diff 跑、本機不 build 文件站；`blueprint:gate` 讀一次分支預覽 build 的結果；`knip --production` 的位置留給死碼分流完成後啟用。

### Shard 2：repository 在真實資料庫上證明（`repository-tests-real-db`）

1. 開始前以 `knip --production` 檢查 repository 層：沒有正式呼叫端的方法列為刪除候選，逐項附理由，由開發者在 G2 決定。
2. 其餘每個 repository 方法至少有一個 `persistence/` 測試，錯誤分支除外。
3. 文件與 entity 的對應、資料庫錯誤的轉換抽成純函式，以不需要 driver 的單元測試涵蓋。
4. 刪除 pass-through CRUD 單元測試，移除 backend 測試設定中的全域 mongoose 與 mongodb stub，依賴它的測試改為自行 mock 所需。

### Shard 3：元件測試改在網路邊界替換，第一批（`component-tests-msw`）

1. 建立 MSW 的測試基礎設施，移除 shared setup 對 `fetch` 的全域替換。
2. 依目錄改寫第一批元件與 hook 測試：不再 mock `apiClient`、自己的子元件與 hook；jsdom 無法執行而必須 mock 自己程式碼的地方，在測試檔中註明原因。
3. `set-options-panel` 的測試保留「等表單的非同步驗證完成才斷言按鈕停用」的等待，否則競態會再出現。

### Shard 4：元件測試改在網路邊界替換，第二批（`component-tests-msw-completion`）

1. 改寫其餘的元件與 hook 測試，完成後 S7 成立。

### 每個 shard 的證明

每個 shard 在自己的 Review tab 交出三項：

1. `pnpm verify:all` 與 `pnpm test:integration` 全部通過。
2. 單元與整合測試合併量測 `src/` 的覆蓋率，以獨立一次執行與 shard 開始前逐檔比較；下降的檔案逐一列出原因。
3. 刪除對照表：每一個刪除或搬移的測試案例，列出現在由哪個測試接手，或為什麼不再需要。

### 順序與相依

- 建立隊伍的原子化修正排在 Shard 1 之後，才能以 transaction 在整合測試中證明。
- 以 Gherkin 規格驅動 acceptance test 的評估排在本 Migration 之後：它的放置位置取決於本頁的分層（ADR-0085 與 ADR-0088 的 revisit trigger）。
- 死碼分流與本 Migration 互不阻擋；Shard 2 只處理 repository 層，其餘交給死碼分流。

### 不在範圍內

- end-to-end 測試與 API smoke 的實作，以及它們需要的、只在測試環境開放的登入方式。
- controller 測試改用真實 use case，等 controller 接手 request parsing 與 mapping 時處理（ADR-0086）。
- `knip --production` 找出的 repository 層以外的死碼。

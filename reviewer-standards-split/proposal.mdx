<TLDR>
`CONTRIBUTING.md` 同時寫給開發者與 standards reviewer，兩份指引檔各自重述 `WORKFLOW.md` 並已漂移，寫作規範（語言切分、頁面標題、元件字串）只存在於口頭交代與 agent 記憶。本 Change 依「誰在什麼時候讀」重新分家：判斷型規則進只在 review 時讀的 `CODING_STANDARDS.md`，寫作時用的規則進寫作者本來就會讀的 `CONTRIBUTING.md` 與 `docs/agents/blueprint.md`，`AGENTS.md` 成為唯一指引檔、`CLAUDE.md` 只 import 它。能機械化的規範改由 `check:workflow` 檢查或直接消滅。同時把 G1 改為開發者在對話中確認 grill 收斂結果，並把綁了十幾個決策的 ADR-0045 拆成單一決策的 record。
</TLDR>

本頁依 ADR-0060 撰寫：內容逐字取自 grill 最後確認的總表。因為本 Change 仍在舊契約下，G1 照舊驗收這一頁。

## 規則去向

`CONTRIBUTING.md` 的清點：

| # | 規則 | 去向 |
| --- | --- | --- |
| 1 | 先讀 `WORKFLOW.md` | `CONTRIBUTING`（指標） |
| 2 | 分支與 PR 流程 | `CONTRIBUTING`（指標，去掉章節編號） |
| 3 | PR 用 en 並附 zh-tw 摘要；PR 不可有 AI 署名 | `CONTRIBUTING` |
| 4 | commit 格式、type、範例 | `CONTRIBUTING`（範例加 commitlint 指標） |
| 5 | commit 用 en；body 寫 why | `CONTRIBUTING` |
| 7 | tooling 名稱不可當 type 或 scope | 刪除（commitlint 已擋） |
| 8 | trailer 格式細節與驗證指令 | `CONTRIBUTING`；哪種 commit 帶哪個 trailer歸 `WORKFLOW` |
| 9 | Airbnb style | 刪除（不是事實） |
| 10 | `pnpm lint`、`pnpm typecheck` | `CONTRIBUTING` |
| 11 | 檔名與識別字命名慣例 | `CODING_STANDARDS`（lint 化另開 ticket） |
| 12 | 註解整節 | `CODING_STANDARDS`，引用格式改為 ADR 編號 |
| 13 | source 中不可放 issue id | `CODING_STANDARDS` |
| 14 | testing strategy | 兩處都放指標 |
| 15–17 | worktree、Changesets、依賴維護 | `CONTRIBUTING` |

指引檔的清點：

| # | 規則 | 去向 |
| --- | --- | --- |
| a、b | vendor skill 不可修改；工具 artifact 不是第二個權威 | 刪除（`WORKFLOW` 已有） |
| c | 判斷型刪除要先確認 | `WORKFLOW` Apply |
| d | 問題等到 gate 再問 | `WORKFLOW` Lifecycle 開頭 |
| e、f | 以 slug 引用 Change；不 hard-wrap 散文 | `CONTRIBUTING` 新增 Writing 一節，`blueprint.md` 指過去 |
| g | commit 格式相關 | 刪除（Q7 已處理） |
| h | Pre-PR 見 §5 | 改為不帶編號的指標 |
| i | PR 開了只等 CI | 刪除，`WORKFLOW` §3 缺的事實補進去 |
| j | See also | 保留 |
| k | 驗收即是開 PR 的許可 | `WORKFLOW` §3 |

**不在範圍內**：命名慣例的 lint 化，另開 ticket。

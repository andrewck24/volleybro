## Decisions

<DecisionCards ids={[]} />

版本 pin 與 CLI 選擇可由後續受檢查 PR 回復，不新增 ADR；不改寫既有 decision records。

## Scope

1. 更新 packageManager 與必要 contributor 設定；只在真實相容性問題需要時修改 workflows／hosted build 設定。保留 action-setup 與 Node runtime，避免為升級而重寫 CI。
2. 保留現有 dependency resolution 與 lockfile；若 frozen install 不相容，停下來釐清，而不是順便升級全部套件。維持 allowBuilds，禁止 blanket approve。
3. `blueprint:gate` 採 global cf 優先、缺少 executable 才 fallback。非零 exit、登入、API、timeout 或 JSON 失敗不切換另一版重試。fallback 保留既有 cf package pin；不把最新版 beta 自動納入 repo。
4. 用 real executable fixtures 驗證 CLI 選擇與 native／JS pnpm 邊界，覆蓋既有 Windows shim 支援；避免只 grep source。其餘 proof 重用現有 full validation、integration lane 與 hosted builds。
5. Changeset 記錄 contributor toolchain 影響，不直接將 package.json version 改成 0.16.0。合併時以真實 remote default 為 base，必須先於 `release-train` 首次 version PR 的授權範圍。

本機 standalone pnpm、授權全域套件清理與 CLI 安裝已執行，與 repo delivery 分開記錄。OAuth 登入由開發者執行，不複製本機登入 token 到 CI。DB、正式網址、release credentials、hotfix 與 dependency automation 均不在本 Change；不將 Changesets 替換為 pnpm 內建 versioning。

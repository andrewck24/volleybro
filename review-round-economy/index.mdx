<TLDR>
Pre-PR code review 每一輪都重審整個 diff，而且同一類問題可能一輪接一輪逐個修補，沒有停損點。`single-page-change` 因此多跑了好幾輪：前面幾輪都在修同一個手寫解析器的新繞過方式。這個 Change 讓第 2 輪起只審上一輪之後的 commit；同一個 root cause 連續兩輪出現時，改用該類問題的最佳實踐修法，記成偏差，到 G2 再交給開發者判斷。
</TLDR>

| | 現在 | 之後 |
| --- | --- | --- |
| 第 2 輪起的 review 範圍 | 整個 diff 對 `dev` | 上一輪審過的 commit 到 HEAD，加上前面各項 finding 的處置 |
| reviewer 無法接續時 | 沒有規定 | 新 reviewer 拿到前面所有輪次的報告與處置 |
| 同一類問題反覆出現 | 每輪逐個修補 | 以 root cause 判定，連續兩輪就換成最佳實踐的做法 |
| 換做法時 | 沒有規定 | 手法或 ADR 內文：記成偏差不停下來；scenario 或 Proposal：走 Ingest |

## 範圍

1. `WORKFLOW.md` 的 Pre-PR 第 4 步：輪次範圍、reviewer 接續、換做法的規則。
2. `docs/agents/blueprint.md`：`Deviations` 如何記錄換做法與判定理由，`ActionItems` 何時要列出被修改的 ADR 內文。
3. ADR-0076、ADR-0077。

`code-review` playbook 不改：後面的輪次只要把上一輪審過的 commit 當作比較基準點傳進去就好。retro 的觸發條件（超過三輪）不變。

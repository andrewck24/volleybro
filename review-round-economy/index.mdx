<Proposal>

<TLDR>
Pre-PR code review 每一輪都重審整個 diff，而且同一類問題可能一輪接一輪逐個修補，沒有停損點。`single-page-change` 因此多跑了好幾輪：前面幾輪都在修同一個手寫解析器的新繞過方式。這個 Change 讓第 2 輪起只審上一輪之後的 commit；同一個 root cause 連續兩輪出現時，改用該類問題的最佳實踐修法，記成偏差，到 G2 再交給開發者判斷。
</TLDR>

| | 現在 | 之後 |
| --- | --- | --- |
| 第 2 輪起的 review 範圍 | 整個 diff 對 `dev` | 上一輪審過的 commit 到 HEAD，加上前面各項 finding 的處置 |
| reviewer 無法接續時 | 沒有規定 | 新 reviewer 拿到前面所有輪次的報告與處置 |
| 同一類問題反覆出現 | 每輪逐個修補 | 以 root cause 判定，連續兩輪就換成最佳實踐的做法 |
| 換做法時 | 沒有規定 | 手法或 ADR 內文：記成偏差不停下來；scenario 或 Proposal：走 Ingest |

## 範圍

1. `WORKFLOW.md` 的 Pre-PR 第 4 步：輪次範圍、reviewer 接續、換做法的規則。
2. `docs/agents/blueprint.md`：`Deviations` 如何記錄換做法與判定理由，`ActionItems` 何時要列出被修改的 ADR 內文。
3. ADR-0076、ADR-0077。

`code-review` playbook 不改：後面的輪次只要把上一輪審過的 commit 當作比較基準點傳進去就好。retro 的觸發條件（超過三輪）不變。

<ActionItems>

1. 接受下方「與 Proposal 的偏差」第 1 項。這是第 3 輪 review 前，依本 Change 自己的停損規則換的做法。只換手法，沒有改動任何 ADR 的 `decision` 內文。

</ActionItems>

<ReviewFocus>

1. `WORKFLOW.md` Pre-PR 第 4 步的兩個子項：輪次範圍、reviewer 接續、以 root cause 判定與換做法。它們是第 4 步迴圈中每一輪的規則，不是迴圈結束後才執行的步驟。
2. ADR-0077 新增的最後一條 `consequences`：decision record 不在 ADR-0075 的凍結範圍內。WORKFLOW 的 Proposal tab 那一行只引用它，不再自己寫一次。
3. `docs/agents/blueprint.md` 對 `ActionItems` 與 `Deviations` 的兩處補充：換做法時，Review tab 的撰寫者要寫什麼。

</ReviewFocus>

<Deviations>

1. **換成「每條規則只有一個 owner」的寫法**。這是依 ADR-0077 自動觸發的做法轉換。
   - 觸發原因：第 1 輪 standards 找到同一條規則分別寫在 ADR、WORKFLOW、Feature 頁，而且已經開始走樣；第 2 輪兩軸又各找到一個新實例。standards 發現凍結範圍的例外沒有任何 ADR 擁有；spec 發現修正只改了 WORKFLOW，Feature 頁沒跟上。
   - 三者算同一個 root cause：都是「一條規則在多份文件各自寫一次，改了一處，其他處就落後」。
   - 新做法：凍結例外寫進 ADR-0077 的 `consequences`，WORKFLOW 引用它；Feature 頁每條規則只寫一行，附上 ADR，不再重述條件分支；changeset 也改成一行。
   - 影響範圍：ADR 只動了 `consequences`，G1 確認過的 `decision` 內文沒有改。

</Deviations>

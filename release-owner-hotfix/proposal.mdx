<TLDR>

目前 hotfix 要求另一個 GitHub 身分 approve exact SHA，單人 repo 因無法 approve 自己的 PR 而被擋住。本 Change 改成指定 release owner 明確 dispatch PR number 與 exact SHA，保留 fresh-context Agent review、可信 CI 與真人部署 QA。不建立第二個自己的帳號，不使用 admin bypass。

</TLDR>

| 邊界 | 目前 | 本次交付 |
| --- | --- | --- |
| Hotfix 發布授權 | 另一位 collaborator 的 exact-SHA PR approval | 指定 release owner 的 exact-SHA manual dispatch，核對原始 actor／rerun actor／可信 main ref |
| 開發審查 | Repository Pre-PR independent review | 保留並在 ready PR／交付證據說明；不宣稱 controller 能從 dispatch 推知 Agent review 已完成 |
| 部署 QA | Required reviewer 檢查 candidate 與 production | 保留；owner 可自行驗收，不要求 Prevent self-review |
| GitHub credentials | 發布驗證與寫入共用 PAT | 授權檢查優先使用 job-scoped read-only GITHUB_TOKEN；版本 PR／需要觸發 CI 的寫入保留 PAT |

## Scope

單張 PR 交付，屬於 `release-train` 的啟用前置修正。既有 Proposal、各 shard Review 與 adopted ADR 保留，不重寫已完成歷史。此授權規則可直接回復，活規則由 WORKFLOW 持有，不另外增加重複 ADR。

1. `WORKFLOW.md`：指定 `RELEASE_OWNER_LOGIN` 為 hotfix dispatch owner；只有 trusted main manual dispatch 可授權 exact PR/head。缺值、非 owner、rerun 身分不符、ref／事件錯誤全部拒絕。每次 head 變更需重新驗證與授權。
2. `.github/workflows/production-release.yml` 與 `scripts/release-controls.js`：由 GitHub event／context 傳遞 actor、triggering actor、ref 與 event name，不接受 PR 內容替代身分。在任何 candidate stage 前檢查；移除強制獨立人類 approval 及僅為此要求存在的 API 判斷。不更動 PR 的 same-repository／open／isolated deployed-base／trusted checks 規則。
3. 使用原生 job-scoped token 執行 read-only 發布授權檢查；保留 PAT 的 Changesets branch／PR 與 merge-back 操作。優先重用既有 permission 與 controller，不建立新 credential framework。
4. 依 test-audit 延伸 `scripts/__tests__/release-controls.test.js` 的公開 CLI owner cases，證明單人授權可用且上述拒絕條件有效，不新增 test-only export。必要時延伸原生 workflow transport proof。
5. 更新 `docs/release-runbook.md` 與最窄 delivery-workflow Feature；與 canonical WORKFLOW 一致，不複製整套操作規則。評估 contributor-facing Changeset。

不包含正式部署、default branch 切換、刪除 dev、DB／OAuth 改動或取消 deployment QA。`RELEASE_OWNER_LOGIN` 實際設定與 environment reviewer 在 G2 接受／合併後核對。平台啟用沿用 `release-train` 的一次性 checklist，只有已被新規則取代的獨立人類 approval 不再作為前置。

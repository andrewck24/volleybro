# Test audit adapter

The vendored `test-audit` skill comes from another repository and names that repository's files, commands and workflow. Read each of its references through this table; everything else in the skill applies as written.

| The skill says                                                               | In VolleyBro                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| boundary and cost guide (`docs/help/testing/writing-tests.md`)               | [`docs/testing-strategy.md`](../testing-strategy.md): its tier table decides the owner boundary, and its Test Value section is the authoring gate this skill serves.                                                                                                 |
| proof policy (`openclaw-testing`)                                            | Run the owner test and its siblings with the tier's runner: `pnpm test <path>` for a unit test, `pnpm test:integration <path>` for an `.itest.ts`, `pnpm test:workflow` for `scripts/`. The gates before the pull request are in `WORKFLOW.md`'s Repository profile. |
| active Vitest checkouts                                                      | Does not apply: VolleyBro runs Jest and `node --test`.                                                                                                                                                                                                               |
| `pnpm deadcode:dependencies`, `deadcode:unused-files`, `deadcode:exports`    | `pnpm knip`, which reports unused files, exports and dependencies in one run.                                                                                                                                                                                        |
| autoreview                                                                   | The `code-review` skill. Give its Standards axis this skill and this adapter alongside `CODING_STANDARDS.md`.                                                                                                                                                        |
| commit, push or land through the native maintainer workflow                  | `WORKFLOW.md`: a Fast path pull request, or the owning Change's, merged only after G2.                                                                                                                                                                               |
| a subsystem such as `extensions/telegram`, or one core area (campaign lanes) | One owner area of `src/`: a layer (`entities`, `applications`, `infrastructure`, `interface`) or one feature's slice across them. A shard of a Change that deletes or moves tests runs as a campaign, with the ledger `docs/testing-strategy.md` defines.            |
| classify the changed gate with `node scripts/check-changed.mjs --dry-run`    | `pnpm verify:all --dry-run` prints which lanes the diff runs.                                                                                                                                                                                                        |
| CI routing, test inventories and shrink-only line-cap baselines              | Jest projects in `jest.config.ts` route tests by path, and VolleyBro keeps no test inventory or line-cap baseline; a moved test only needs the tier home `docs/testing-strategy.md` names.                                                                           |
| durable test-ownership rules in the subsystem's `AGENTS.md`                  | `docs/testing-strategy.md`, the one home for test rules.                                                                                                                                                                                                             |

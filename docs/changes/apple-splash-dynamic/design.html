apple-splash-dynamic

Design · presentation layer (Next route + root layout)

Goals / Non-Goals

Goals

  • One parametric route replaces nine stored PNGs.
  • Background driven by --primary so it tracks rebrands.
  • “V” rebuilt as vector polygons — no dependency on the lost vector or the square icon.
  • Preserve the existing nine-config device coverage.

Non-Goals

  • Regenerating the app icon to match --primary (#0D5365 ≠ #10687E) — separate future change.
  • Landscape / iPad / dark-mode coverage.
  • Offline precaching of generated screens (iOS fetches at install, online).

Decisions

D1 · Runtime generation via next/og ImageResponse

Route Handler returns an ImageResponse — zero new dependency (bundled with Next 16), no build step, no stored binaries. iOS fetches startup images online at install, so runtime is fine.

D2 · Size from the route segment, validated against a fixed list

The handler reads <width>x<height> from one dynamic segment; a module-level list of fifteen pairs (12 iPhone, 3 iPad) is the source of truth. Unknown size → 404 (iOS ignores mis-sized startup images anyway).

D3 · “V” mark as two inline polygons, centered

Two filled polygons traced from icon-512x512.png in a 512×512 space: left arm 88,98 208,98 285,405 168,405 fill #F6F4F5; right arm 308,98 422,98 338,405 312,392 fill #FC7A56. Scaled to a fraction of the shorter device dimension, centered on full-bleed #10687E. No <img>.

D4 · Fifteen device configs are the shared source of truth

The same fifteen { media, width, height } entries drive both the layout’s startupImage list and the route’s accepted-size validation, so coverage and accepted sizes cannot drift apart. iPhone entries carry dpr 2 or 3; iPad entries carry dpr 2.

Data flow

devices.ts (15 configs) →layout.tsx · startupImage urls   &   route.tsx · isSupportedSize + ImageResponse

Approved design comp

Implementation contract

Behavior
Installing the PWA shows the “V” centered on --primary at the device’s exact resolution, matching the bareV draft.
Interface
GET src/app/apple-splash/[size]/route.tsx → ImageResponse of exact size, or 404. Shared devices.ts consumed by route + layout.
Failure
Unsupported size → HTTP 404, no fallback image.
Acceptance
/apple-splash/1290x2796 → 1290×2796 PNG; /apple-splash/100x100 → 404; head has 15 links, none under public/apple-splash/; that directory has no PNGs; visual check vs bareV.

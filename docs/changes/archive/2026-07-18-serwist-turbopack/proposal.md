## Summary

Migrate the PWA service-worker integration from serwist configurator mode (standalone CLI build producing a static public/sw.js) to @serwist/turbopack (service worker generated by a prerendered Next.js route handler).

## Motivation

Configurator mode predates Serwist's Turbopack support and costs us a parallel dev process and a second build step: the dev script runs concurrently to keep a serwist CLI watcher alive next to next dev, and the build script chains a separate serwist build after next build. @serwist/turbopack is Serwist's primary recommendation for Next.js 16 under Turbopack: the service worker is compiled by a route handler that Next prerenders at build time, so dev collapses to plain next dev (the worker rebuilds on change) and build collapses to plain next build. The migration removes three dependencies (@serwist/next, @serwist/cli, concurrently) and adds two (@serwist/turbopack, esbuild).

A full prototype evaluation (Paca VB-52, 2026-07-17) verified: the same src/app/sw.ts compiles unchanged apart from import sources; the prerendered route ships correct Service-Worker-Allowed and Content-Type headers and is served as a static CDN asset on Vercel; withSerwist() composes with the existing withBundleAnalyzer wrapper; and the precache manifest matches the configurator output 1:1 for all build chunks and public assets.

## Proposed Solution

Replace the build-time CLI integration with the route-handler integration:

- Add a service-worker route handler at src/app/serwist/[path]/route.ts using createSerwistRoute with the existing src/app/sw.ts as swSrc and useNativeEsbuild enabled.
- Wrap the Next config with withSerwist (composing with withBundleAnalyzer).
- Repoint the worker-side and client-side imports from @serwist/next to @serwist/turbopack (defaultCache from the worker entry, SerwistProvider from the react entry).
- Register the service worker from its new URL /serwist/sw.js (root scope granted via the baked Service-Worker-Allowed header).
- Simplify the dev script to next dev and the build script to next build; delete serwist.config.js; swap the dependencies accordingly.
- public/sw.js and public/sw.js.map stop being produced; ensure they are not tracked and are covered by .gitignore.

Accepted behavior deltas (decided during evaluation, Paca VB-52):

- The service worker URL changes from /sw.js to /serwist/sw.js. Existing installations pick up the new registration on their next online visit through the standard service-worker update flow.
- Ten prerendered navigation-shell HTML documents leave the install-time precache (114 entries / 7.93 MB becomes 104 entries / 7.12 MB) and are cached at first visit by the runtime PAGES handler instead. These shells render skeletons without network data, recording routes are dynamic and were never precached, and the app has no offline recording feature yet - so install-time parity via additionalPrecacheEntries is deliberately NOT configured.

## Non-Goals

- No offline-first functionality for match recording (future work will need IndexedDB plus background sync, not HTML precache).
- No changes to runtime caching strategies (defaultCache from Serwist is used as-is, same as today).
- No install-time precache parity for navigation shells (additionalPrecacheEntries deliberately omitted; rationale above).
- No changes to PWA metadata surfaces (manifest, apple splash generation, icons).

## Alternatives Considered

- Stay on configurator mode: remains officially supported, but keeps the dual-process dev loop and second build step for no benefit; the community concern that pushed some users back to configurator mode (environment-variable injection, serwist discussion 323) does not apply because src/app/sw.ts reads no environment variables.
- Migrate but restore install-time parity with additionalPrecacheEntries: rejected because the ten shells are skeleton-only without network data; carrying a manually maintained route list adds drift risk for near-zero offline value.

## Impact

- Affected specs: new capability pwa-service-worker
- Affected code:
  - New: src/app/serwist/[path]/route.ts
  - Modified: next.config.js, src/app/sw.ts, src/app/serwist-provider.tsx, src/app/layout.tsx, package.json, pnpm-lock.yaml, .gitignore
  - Removed: serwist.config.js

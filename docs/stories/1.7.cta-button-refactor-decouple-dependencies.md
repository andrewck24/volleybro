# Story 1.7: CTA Button 重構與相依關係解耦

## Status

Done

## Story

**As a** 開發維護者，
**I want** CTA Button 元件具有統一設計且不依賴元件間耦合，
**so that** 程式碼更易於維護且視覺呈現更一致

## Acceptance Criteria

1. Header 與 Hero 元件完全解耦
2. CTA Button 顏色配置在 Light/Dark mode 都有鮮明對比
3. 所有 CTA 按鈕設計統一且無邊框
4. PWA 安裝功能保持完整
5. 新的 CTA 元件測試涵蓋重構後的功能

### Component Specifications

[Source: 現有 src/components/landing/header.tsx 分析]

**當前 Header-Hero 耦合結構**:

- **觀察者模式**: Header 接收來自 Hero 的 `observerRef`
- **交集偵測**: 使用 `IntersectionObserver` 監測 Hero 中 CTA 區域的可見性
- **CTA 顯示邏輯**: `setIsShowingCTA(!entry.isIntersecting)` 控制 Header CTA 透明度
- **滾動偵測**: 同時使用 `useScroll` 監測滾動狀態觸發 glassmorphism

[Source: 現有 src/components/landing/hero.tsx 分析]

**當前 Hero 元件結構**:

```typescript
const observerRef = useRef<HTMLDivElement | null>(null);
// ...
<Header observerRef={observerRef} />
<div ref={observerRef} className="...CTA區域...">
  <CTAButton />
</div>
```

[Source: 現有 src/components/landing/cta-button.tsx 分析]

**當前 CTA Button 功能**:

- **PWA 檢測**: 檢測平台類型（iOS/desktop/mobile）和安裝狀態
- **安裝提示**: 支援不同平台的 PWA 安裝流程
- **樣式變體**: 當前使用 `variant="outline"`
- **邊框設計**: Hero 中 CTA 使用 `border-0` 覆蓋，Header 中保持預設邊框

### Security Considerations

**解耦後元件通信安全性**:

- **狀態隔離**: Header 與 Hero 解耦後，消除了 observerRef 跨元件狀態共享，減少意外狀態洩漏風險
- **Props 安全**: 移除 observerRef props 傳遞，降低意外 DOM 操作或狀態注入的潛在攻擊面
- **元件邊界**: 各元件現在有明確的責任邊界，便於安全審查與漏洞追蹤
- **PWA 安全**: CTA Button 的 PWA 安裝檢測功能維持既有的平台檢測與用戶互動安全機制

### Performance Considerations

[Source: architecture/11-performance-optimization.md]

- **Bundle Size**: 移除 Header-Hero 耦合邏輯可能輕微減少 bundle 大小
- **Render Performance**: 簡化 Header 元件狀態管理，減少不必要的重渲染
- **Layout Stability**: 確保架構重構不造成 CLS (Cumulative Layout Shift)
- **PWA Performance**: 維持 CTA Button 的 PWA 檢測與安裝功能效能

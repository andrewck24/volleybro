## Story

**I want** to implement modern i18next integration with Next.js App Router using best practices recommended by official documentation,
**so that** the application supports multiple languages (English and Traditional Chinese) with optimal SSR performance, simplified routing, and automatic language detection without manual configuration in each page.

## Dev Notes

### Locize App Router 整合方法

[Source: https://www.locize.com/blog/i18n-next-app-router]

**核心優勢**：

- 無需在每個頁面手動傳遞語言或翻譯函數
- 通過 middleware 自動從 URL 提取語言
- 使用 headers 在伺服器端傳遞語言資訊
- 統一的 `getT()` 和 `useT()` 介面

**關鍵實作原理**：

```typescript
// middleware 自動語言偵測
export async function middleware(request: NextRequest) {
  const pathname = request.nextUrl.pathname;
  const locale = getLocaleFromPath(pathname) || detectLocale(request);
  response.headers.set("x-lng", locale);
}

// 伺服器端翻譯載入
export async function getT(ns, options) {
  const headerList = await headers();
  const lng = headerList.get("x-lng");
  // 動態載入語言和命名空間
}
```

### 與傳統方法的技術差異

**傳統 Pages Router 方法**：

- 需要 `serverSideTranslations` 在每個頁面
- 使用 `appWithTranslation` HOC
- 複雜的 SSR/Client 狀態同步

**現代 App Router 方法**：

- Middleware 自動處理語言路由
- Headers 傳遞語言資訊給伺服器元件
- 統一的翻譯函數介面，無需頁面級配置
- 完美的 SSR/Client 一致性

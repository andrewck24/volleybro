## Story

**As a** 網站效能管理者，
**I want** 大幅減少 motion 相關的 bundle size 並改善運行時效能，
**so that** 使用者在載入頁面時能獲得更快的初始載入體驗，尤其是在低階裝置和慢速網路環境下。

## Dev Notes

### Previous Story Insights

基於 Story 1.11 完成狀況，landing page 元件架構已穩定，所有 FeatureCard 和相關動畫效果運作正常。此次優化可安全進行 motion 元件轉換而不影響既有功能。

### 核心技術問題分析 [Source: GitHub Issue #253]

- **Bundle Size 問題**: 當前使用完整 `motion` 元件 (~34kb)，實際僅需基礎動畫和手勢功能
- **Tree Shaking 不足**: 未充分利用 bundler 的 tree-shaking 能力
- **功能載入策略**: 缺乏 LazyMotion 進行功能分割和延遲載入
- **潛在警告**: 三個浮動元素使用 motion props 可能觸發 React DOM 警告

### 技術架構決策 [Source: docs/architecture/tech-stack.md]

- **Motion Framework**: Motion 12.6.3 作為 Framer Motion 後繼者，支援 LazyMotion 架構
- **Bundle 優化**: Next.js 15.4.6 內建 Tree Shaking 和程式碼分割功能
- **TypeScript**: 5.8.3 嚴格型別檢查，確保 motion/react-m 轉換的型別安全

### LazyMotion 實作細節 [Source: motion.dev 官方文件]

**個別元件包裝策略** (更佳實踐):

```tsx
// 個別元件包裝 - 模組化且精確控制
import { LazyMotion, domAnimation } from "motion/react";
import * as m from "motion/react-m";

export const CTASection = () => {
  return (
    <LazyMotion features={domAnimation} strict>
      <m.section animate={{ opacity: 1, y: 0 }}>{/* 元件內容 */}</m.section>
    </LazyMotion>
  );
};

// 元件層級轉換
import * as m from "motion/react-m"; // 替代 import { motion } from "motion/react"
```

**優點**:

- 模組化: 每個元件獨立包裝，不影響其他元件
- 精確控制: 只有需要動畫的元件才載入功能包
- 更佳性能: 避免全域載入不必要的功能

### 效能最佳化目標 [Source: GitHub Issue #253 Analysis]

- **初始載入**: 4.6kb (m + LazyMotion)
- **延遲載入**: 15kb (domAnimation 功能包)
- **總體減少**: 從 34kb 降至 19.6kb (-42%)
- **功能覆蓋**: domAnimation 包含 animations, variants, tap/hover/focus gestures（滿足當前需求）

### 無障礙性支援需求 [Source: Web Standards]

```tsx
import { useReducedMotion } from "motion/react";

const CTABackgroundEffects = () => {
  const shouldReduceMotion = useReducedMotion();

  if (shouldReduceMotion) {
    return <StaticBackgroundEffects />;
  }
  return <AnimatedBackgroundEffects />;
};
```

### 測試環境共存策略 [Source: docs/architecture/08-testing-strategy.md]

採用 motion 和 m 元件共存的測試策略，避免替換現有穩定的 mock：

```typescript
// jest.setup.ts 更新策略 - 補充而非替換
jest.mock("motion/react", () => {
  // 保持現有 motion mock 穩定性
  const filterMotionProps = (props: any) => {
    /* 現有邏輯 */
  };

  return {
    __esModule: true,
    motion: {
      /* 現有 motion 元件 mock */
    },
    // 新增 LazyMotion 相關支援
    LazyMotion: ({ children }: any) => children,
    domAnimation: {},
    useReducedMotion: () => false,
  };
});

// 新增 motion/react-m 獨立 mock
jest.mock("motion/react-m", () => ({
  m: {
    section: ({ children, className, ...props }: any) =>
      React.createElement("section", filterMotionProps(props), children),
    div: ({ children, className, ...props }: any) =>
      React.createElement("div", filterMotionProps(props), children),
    // 其他 m 元件...
  },
}));
```

**共存策略重點**:

- 保持現有 `motion` mock 不變，確保測試穩定性
- 新增 `motion/react-m` 獨立 mock，支援 LazyMotion 優化元件
- LazyMotion wrapper 在測試環境直接渲染 children
- useReducedMotion hook 預設為 false（啟用動畫測試）

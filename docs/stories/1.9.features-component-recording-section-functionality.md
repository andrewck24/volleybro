### TDD Testing Requirements

**[Source: architecture/coding-standards.md#test-driven-development]**

TDD 開發流程：

1. **紅燈階段**：
   - 在 features.test.tsx 中撰寫 Features 元件 Fragment 架構測試
   - 撰寫 FeatureCard 佈局控制測試（透過 className）
   - 撰寫 RecordingSection 內容展示測試
   - 確保所有測試失敗

2. **綠燈階段**：
   - 實作最小可行程式碼通過測試
   - 專注功能實現，不考慮最佳化

3. **重構階段**：
   - 優化元件結構和效能
   - 確保測試持續通過

### Specific Test Cases

在 `features.test.tsx` 中包含：

1. **Features 元件測試**：
   - 驗證使用 React Fragment 包裝三個功能區塊
   - 確保現有動畫效果與視覺設計保持一致
   - 測試響應式佈局在各種斷點下正確顯示

2. **FeatureCard 元件測試**：
   - 測試透過 className 控制的佈局方向（lg:flex-row vs lg:flex-row-reverse）
   - 驗證卡片高度 70vh 和 1:1 展示區域
   - 測試響應式佈局切換（桌面端水平，行動端垂直）

3. **RecordingSection 測試**：
   - 驗證兩個卡片均使用圖右文左佈局
   - 測試卡片內容正確顯示（標題、描述）
   - 確保與設計系統一致性

### Testing Patterns

**[Source: architecture/coding-standards.md#testing-patterns]**

必須遵循的測試標準：

- 使用 `data-testid` 屬性進行可靠元素選擇
- 優先使用語意查詢（getByRole、getByLabelText）
- 測試使用者互動，非實作細節

重點：撰寫測試時，應注重實際行為而非實現細節，確保測試覆蓋功能正確性。若非 RWD 等與樣式相關的功能，不要以樣式進行測試。

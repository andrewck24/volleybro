## Dev Notes

### Previous Story Insights

Story 1.1 已完成 Hero 區塊的性能優化，移除了 scroll-driven 動畫和 hover 效果，簡化了動畫結構。Story 1.4 將實現 Header 的 glassmorphism 效果。Hero 元件重構應該遵循同樣的簡化和主題統一原則。

### Architecture Context

[Source: architecture/03-architecture-overview.md#Clean Architecture 分層]

- Frontend Stack: React 19 + Next.js 15 + TypeScript
- UI Components: Tailwind CSS + Shadcn/UI + Motion/React
- 元件架構: 領域驅動設計，單一職責原則
- 測試策略: Jest + React Testing Library

### Component Specifications

[Source: 現有 src/components/landing/hero.tsx 分析]
現有 Hero 元件結構（156 行程式碼）：

- Badge 顯示 Preview 版本
- 主標題與 FlipWords 文字輪播
- 描述文字段落
- CTAButton 行動召喚（維持整合在主元件）
- 三大特色標籤展示
- 右側圖片展示
- 背景動畫和裝飾元素

### 元件拆分策略

**核心子元件**:

- `HeroBadge`: Preview badge 獨立元件
- `HeroTitle`: 主標題與文字輪播
- `HeroDescription`: 描述文字元件
- `HeroFeatures`: 三大特色標籤
- `HeroImage`: 右側圖片展示

**保持整合在主元件**:

- CTAButton: 維持在主元件內，不拆分
- 背景動畫元素: 保持在主元件統一管理

**重構目標**:

- Hero 主元件 < 80 行程式碼 (當前 156 行)
- 每個子元件 < 50 行程式碼
- 清晰的 props 介面定義
- 獨立的測試覆蓋

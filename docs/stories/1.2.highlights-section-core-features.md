### Four Core Features Content

根據 Epic 1.2 規格：

**1. 即時記錄**：
- 標題：「提供簡單易用的賽事記錄工具」
- 描述：讓教練能夠快速記錄比賽數據，告別繁瑣的紙筆作業
- 重點：簡單性、快速性、無紙化

**2. 視覺化數據分析**：
- 標題：「透過強大的數據分析功能」
- 描述：深入了解球隊表現，以數據驅動戰術改進
- 重點：數據洞察、戰術支援、表現分析

**3. 團隊管理**：
- 標題：「有效掌握球員資訊與表現變化」
- 描述：協助陣容安排，讓每場比賽都有最佳配置
- 重點：球員管理、陣容優化、配置策略

**4. 跨平台支援**：
- 標題：「無論是手機、平板或電腦」
- 描述：隨時隨地輕鬆使用，不受設備限制
- 重點：設備相容、便利性、隨時存取

### TDD Testing Strategy

**[Source: architecture/coding-standards.md#test-driven-development]**

TDD 開發流程：

**1. 紅燈階段（Red Phase）**：
- 先撰寫測試案例，明確定義預期行為
- 確保所有測試失敗，驗證測試的有效性
- 涵蓋正常情況、邊界情況、錯誤情況

**2. 綠燈階段（Green Phase）**：
- 實作最小可行程式碼讓測試通過
- 專注功能實現，不考慮最佳化
- 確保所有測試從失敗轉為成功

**3. 重構階段（Refactor Phase）**：
- 優化程式碼結構和效能
- 保持測試持續通過
- 改善程式碼品質和可維護性

### Testing Patterns

**[Source: architecture/coding-standards.md#testing-patterns]**

必須遵循的測試標準：

- 使用 `data-testid` 屬性進行可靠元素選擇
- 優先使用語意查詢（getByRole、getByText）
- 測試使用者可見的行為，非實作細節
- 模擬 Motion 動畫相關依賴

```tsx
// 測試範例
describe('HighlightsSection TDD Implementation', () => {
  describe('Red Phase - Failing Tests', () => {
    it('should render four feature highlight cards', () => {
      render(<HighlightsSection />);
      
      // 這些測試一開始會失敗
      expect(screen.getByTestId('highlights-section')).toBeInTheDocument();
      expect(screen.getAllByTestId('highlight-card')).toHaveLength(4);
    });

    it('should display correct feature titles and descriptions', () => {
      render(<HighlightsSection />);
      
      // 測試四大特色內容
      expect(screen.getByText('提供簡單易用的賽事記錄工具')).toBeInTheDocument();
      expect(screen.getByText('透過強大的數據分析功能')).toBeInTheDocument();
      expect(screen.getByText('有效掌握球員資訊與表現變化')).toBeInTheDocument();
      expect(screen.getByText('無論是手機、平板或電腦')).toBeInTheDocument();
    });
  });
});
```

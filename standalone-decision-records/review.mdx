<TLDR>
65 個檔案成為 53 份記錄，住在扁平的 `blueprint/content/decisions/`；Feature 頁改依 `capabilities` 過濾渲染，不再逐條 import。schema 升到 version 2，required 五個欄位，`originDecision` 刪除，store 分支上的 version 1 記錄透過相容層繼續渲染。八個驗收 scenario 有七個由測試證明，第八個（編號於誕生時取 max+1）是寫入當下的紀律，沒有程式能驗——這是唯一的殘留風險。兩軸 code review 跑了兩輪達到不動點，六個發現全部處置，其中最嚴重的一個是我自己把 2,857 行無關檔案掃進了第一個 commit。
</TLDR>

## 邊界上最關鍵的一段 diff

相容層是整個 Change 唯一會一次弄垮所有已發佈 Change 頁的地方。它的形狀是：parser 自己讀得懂 version 1，而 `status` 的豁免留在 legacy 層——所以 `status` 只有舊頁面可以帶，沒有隨著 version 1 的支援一起變成全域合法。

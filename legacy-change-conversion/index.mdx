## 範圍

### Shard 1：機械轉換與刪除

1. 以 `scripts/migrations/` 下的一次性腳本轉換 22 頁，用完即刪：
   - frontmatter 取自 `change.json` 的 title 與 capabilities，tags 丟棄；`facts.json` 由腳本從 `change.json` 的日期推導，不手抄其他數字。
   - Proposal tab 開頭以一行普通段落（不用引文框）註明「由舊格式機械轉換，未經 G1／G2；持久知識見 Features 與決策記錄」，草稿另註「未通過 G1」。
   - `index.mdx`、`proposal.mdx`、`design.mdx` 的 `TLDR`、散文、`AnnotatedDiff`、`InteractiveFlowchart` 原文放進 Proposal tab。
   - 舊 change 內的 ADR 改用 `DecisionCards` 引用全域編號。
   - `review.mdx` 的散文與 `RiskTable` 放進 Review tab 的 `ReviewDetails`，並留一行 PR 連結。
   - `design.tsx` 原樣保留。
   - 丟棄：`FileTour`、`TaskProgress`、兩個 `Workflow*` 元件、`implementation/`、`tasks.mdx`、`Scenario`、`specs/`（由 Shard 2 處理）。
2. `record-flows` 與 `sync-recording` 是從未通過 G1 的草稿，只產生 Proposal tab；它們的決策以靜態文字保留，不寫進決策目錄，因為 Features 頁會把目錄裡的記錄列為已實作。
3. 刪除 `legacy` 目錄、四個舊元件與它們的測試，以及 route、Changes 索引、`DecisionTimeline` 對它們的依賴。
4. 修改 `WORKFLOW.md`（歷史快照保持原樣的規則、store 分支記錄經相容層讀取的段落）、`docs/agents/artifact-lifecycle.md`（Spectra 快照不可變）與 `docs/agents/blueprint.md`（轉換頁規則），改寫成 ADR-0079 的規則。

### Shard 2：知識提升

1. 6 個 Spectra change（`api-objectid-guards`、`apple-splash-dynamic`、`contextual-edit-pages`、`elevation-depth-system`、`entry-ui`、`team-routes-clean-architecture`）的每條 requirement 對照現行程式碼：
   - 有程式碼或測試證據的，以 Features 現有格式寫進對應 capability；證據列在 Review tab，不寫進 Features 本文。
   - 被後續 change 改掉的，照現行行為寫。
   - 沒做完的，不寫入，列在 Review tab 的 `ActionItems` 由開發者決定。

每個 shard 是各自的 pull request，跳過 G1、直接到 G2。Shard 2 以它自己的 Change 頁過 G2。

### 不在範圍內

- 讓 Features 改用 given/when/then 或導入可執行的 Gherkin 測試，另案評估。
- `record-flows` 與 `sync-recording` 的決策核對與入庫，在它們各自的 G1 處理。
- decision-record schema 的驗證與 store 分支保留政策，在 Shard 1 合併後另案處理。

<Deviations>

1. **Spectra 快照的規則是收窄，不是改寫。** `WORKFLOW.md` 與 `artifact-lifecycle.md` 說 Spectra／OpenSpec 產物是不可變的快照；那兩句也涵蓋 `docs/specs/` 與 `docs/changes/archive/`，Shard 2 正要依這條規則從那裡提升仍然成立的知識。所以我把範圍收窄到 `docs/`，另外寫明 store 分支上的 Change 頁依 ADR-0079 轉換。
2. **多刪了三處只為舊格式存在的程式碼。** `decision-record.ts` 的 version 1 解析、Change 頁元件表裡的 `DecisionTimeline`、Design System 頁的 `FileTour` 展示，都只為舊頁存在。另外把 ADR-0050 標為被取代，你已在 G2 確認。
3. **跳過舊頁的方式改了。** `check:workflow` 原本以 `change.json` 判斷，改由轉換腳本在 `facts.json` 寫入 `converted: true`。
4. **`game-positional-writes` 的名詞說明改成定義清單。** 它的 mockup 用 `FileTour` 呈現一份名詞說明。直接丟棄會留下空的段落和沒用到的資料，所以改成一般的定義清單，內容照舊。
5. **草稿在索引上標為 draft。** 兩份草稿沒有 gate，原本會顯示成「G1 Proposal」，看起來像在等 G1。
6. **三頁沒有 PR 連結。** `api-objectid-guards`、`entry-ui`、`team-routes-clean-architecture` 早於 PR 流程，找不到合併它們的 PR；`team-routes-clean-architecture` 也沒有舊的 Review 頁，所以沒有 Review tab。
7. **第 3 輪 review 前換了做法（ADR-0077）。** 標準軸前兩輪都找到刪除後殘留的過時引用：註解、名稱、Design System 的對照表。root cause 相同：刪了程式碼，卻沒有回頭重讀提到它的地方。於是改為一次搜尋所有被刪的名稱與舊格式用語，逐一處理。第 3 輪回到全範圍審查。
8. **順手修了一行 Features。** `platform/delivery-workflow` 還寫著 Change 的審查頁是 `proposal.mdx` 與 `review.mdx`，和 `platform/blueprint` 矛盾，改為單頁。兩頁格式殘留的程式碼另開後續處理，不在本 Change。
9. **G2 第一輪的要求。** 你在 G2 回覆：
   - 接受 ADR-0050 由 ADR-0079 取代。
   - 不保留舊 Change 的 `implementation.mdx`。
   - 修正 Proposal 裡「`team-membership-authorization` 的決策遺失」的錯誤陳述：四份決策本來就在（ADR-0041 到 ADR-0044）。TLDR、頁面描述與 Shard 2 的「補回決策」一項都已拿掉，並依你的同意重新發布 G1 版本。
   - `next dev` 的記憶體問題維持現狀，列為殘留風險；成因已查明，見殘留風險。
   - 拿掉拒絕 version 1 記錄的測試案例，因為已經沒有、也不會再產生 version 1 記錄。
   - 側欄上每個 Change 仍顯示展開箭頭，交給兩頁格式清理的後續工作一併處理，不在本 Change。

</Deviations>

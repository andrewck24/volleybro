## 範圍

### Shard 1：機械轉換與刪除

1. 以 `scripts/migrations/` 下的一次性腳本轉換 22 頁，用完即刪：
   - frontmatter 取自 `change.json` 的 title 與 capabilities，tags 丟棄；`facts.json` 由腳本從 `change.json` 的日期推導，不手抄其他數字。
   - Proposal tab 開頭以一行普通段落（不用引文框）註明「由舊格式機械轉換，未經 G1／G2；持久知識見 Features 與決策記錄」，草稿另註「未通過 G1」。
   - `index.mdx`、`proposal.mdx`、`design.mdx` 的 `TLDR`、散文、`AnnotatedDiff`、`InteractiveFlowchart` 原文放進 Proposal tab。
   - 舊 change 內的 ADR 改用 `DecisionCards` 引用全域編號。
   - `review.mdx` 的散文與 `RiskTable` 放進 Review tab 的 `ReviewDetails`，並留一行 PR 連結。
   - `design.tsx` 原樣保留。
   - 丟棄：`FileTour`、`TaskProgress`、兩個 `Workflow*` 元件、`implementation/`、`tasks.mdx`、`Scenario`、`specs/`（由 Shard 2 處理）。
2. `record-flows` 與 `sync-recording` 是從未通過 G1 的草稿，只產生 Proposal tab；它們的決策以靜態文字保留，不寫進決策目錄，因為 Features 頁會把目錄裡的記錄列為已實作。
3. 刪除 `legacy` 目錄、四個舊元件與它們的測試，以及 route、Changes 索引、`DecisionTimeline` 對它們的依賴。
4. 修改 `WORKFLOW.md`（歷史快照保持原樣的規則、store 分支記錄經相容層讀取的段落）、`docs/agents/artifact-lifecycle.md`（Spectra 快照不可變）與 `docs/agents/blueprint.md`（轉換頁規則），改寫成 ADR-0079 的規則。

### Shard 2：知識提升

1. 6 個 Spectra change（`api-objectid-guards`、`apple-splash-dynamic`、`contextual-edit-pages`、`elevation-depth-system`、`entry-ui`、`team-routes-clean-architecture`）的每條 requirement 對照現行程式碼：
   - 有程式碼或測試證據的，以 Features 現有格式寫進對應 capability；證據列在 Review tab，不寫進 Features 本文。
   - 被後續 change 改掉的，照現行行為寫。
   - 沒做完的，不寫入，列在 Review tab 的 `ActionItems` 由開發者決定。

每個 shard 是各自的 pull request，跳過 G1、直接到 G2。Shard 2 以它自己的 Change 頁過 G2。

### 不在範圍內

- 讓 Features 改用 given/when/then 或導入可執行的 Gherkin 測試，另案評估。
- `record-flows` 與 `sync-recording` 的決策核對與入庫，在它們各自的 G1 處理。
- decision-record schema 的驗證與 store 分支保留政策，在 Shard 1 合併後另案處理。

<TLDR>
  `check-workflow.js` 幾乎每個 Change 都在加規則，而每條規則的行為同時寫在程式碼、WORKFLOW.md
  與 Feature 三處，改一處就可能與另一處矛盾。這個 Change 刪掉已無作用或只綁住文字的檢查，讓檢查的行為只寫在它自己的失敗訊息裡，並把
  gate 的步驟順序收進 `pnpm blueprint:gate` 一個指令。
</TLDR>

|                        | 現在                                                             | 之後                                                         |
| ---------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------ |
| 一條檢查做什麼         | 寫在程式碼、WORKFLOW.md、delivery-workflow Feature 三處          | 只寫在失敗訊息與測試裡                                       |
| gate 的步驟順序        | WORKFLOW.md 的文字，可能與檢查矛盾                               | `pnpm blueprint:gate <slug>` 依序執行                         |
| Ingest 重設 G1 基準    | 手動剪掉 Review tab、publish、再貼回                              | `pnpm blueprint:gate <slug> --gate G1`                        |
| Spectra 時期的檢查     | 4 條仍在跑，防止已不存在的東西回來                                | 刪除                                                         |

## 範圍

1. **刪除**：`retired-workflow`、`active-legacy-change`、`retired-authority`、`retired-reference` 四條 Spectra 時期的檢查；`standards-reviewer`（要求 WORKFLOW 的 Pre-PR 段落提到或不提到某個檔名）。
2. **保留**：`guidance-import`、`workflow-bridge`、`section-reference`、`shared-skills`、`internal-link`、snippet 檢查——各自擋住真實會發生的退化。
3. **精簡**：`delivery-profile` 的 `SUPPORTED_ADAPTERS` 只留實際需要的 binding；`canonical-contract` 與 `repository-adapter` 兩個檔案存在性檢查合併。
4. **新增** `pnpm blueprint:gate <slug> [--gate G1]`：拒絕未 push 的分支、publish、跑 gate check、印出 branch preview 網址與要比對的 commit 數；`--gate G1` 先只發布 Proposal 再發布整頁。
5. **文件**：WORKFLOW.md 的 G1、Ingest、Archive 與 G2 段落改為執行此指令；刪除 delivery-workflow Feature 的檢查清單；`docs/agents/blueprint.md` 同步。

### 不在範圍內

- Fix path 的邊界（流程規則、小型行為變更、只修措辭的 scenario）：另一個 Change，排在這個之後。
- 在 `platform/blueprint` 畫生命週期流程圖：另案，這個 Change 之後依新指令繪製。

<Review>

<ActionItems>

1. **ADR-0083 要不要擴及產品程式碼的 Feature？** 全文掃描時看到 `platform/clean-architecture`、`platform/error-handling` 也描述了測試會擋下什麼（例如「A test walks `src/` and fails on…」）。那是產品架構的約束，不是交付流程的 gate，這次沒有動；ADR-0083 的字面範圍是「a mechanical check」，是否適用請你決定。
2. **沒有採納 `--gate G1` 改名為 `--g1` 的建議。** 這個旗標寫在 G1 凍結的 S6 與 ADR-0084，改名需要 Ingest。
3. **review 走了三輪**，第二輪同一根本原因連續出現，依 ADR-0077 換了做法，見 Deviations 第 2 點。

</ActionItems>

<ReviewFocus>

1. `scripts/blueprint-gate.js`：新指令本身，特別是 `--gate G1` 先發布 Proposal 再發布整頁的順序。
2. `scripts/check-workflow.js` 被刪掉的規則：每條刪除的理由都在 Proposal 範圍第 1 點，值得確認沒有漏掉仍在守的東西。
3. `WORKFLOW.md` 的 G1、Ingest、Archive、G2 段落：步驟改成執行指令後，讀起來是否仍然完整。

</ReviewFocus>

<Deviations>

1. **範圍第 3 點「`SUPPORTED_ADAPTERS` 只留實際需要的 binding」改為整個刪除。** `REQUIRED_BINDINGS` 已經要求每個 capability 綁定特定 adapter，留下的清單只會與它重複；錯誤的 adapter 現在以 `volleybro-binding` 失敗並指名 capability（S2）。
2. **第三輪 review 換了做法（ADR-0077）。** 根本原因：改寫文件時只把步驟換成指令，卻留下周圍描述檢查行為的文字。第一輪修了被點名的幾處，第二輪在 Feature 又找到一處，於是改由獨立 agent 逐行讀完所有交付流程文件，再逐條判斷；只剩那一處屬於重述，其餘是第三方工具、平台行為或 ADR 定義的能力。
3. **超出範圍列舉的文件也一併修正**：`WORKFLOW.md` 的 Fix path 分支規則與 Change scope 段落、delivery-workflow Feature 的 commitlint 與 `AGENTS.md` 條目。它們都是 ADR-0083 所說的重述，不修就留下同一類矛盾。

</Deviations>

## Findings 與實際修正

- 前批 G2 後的 CodeQL 修正已合併：release controller 在 candidate checkout 前由可信 first-parent 封存為 same-run immutable artifact，移除 release cache；後續 privileged jobs 不再 checkout candidate-derived controller ref。保留原批凍結 Review，這項後續證據放在本批與 Git／PR 歷史，不覆寫過去的人類驗收。

- Standards 發現 read-only inspect 缺少 Check Runs／Statuses API 權限；補 `checks: read`／`statuses: read`，沒有增加 production access。
- Spec 發現 Vercel context 同名不等於可信來源。Live status API 確認 bot creator，共用 helper 以 id／login／type 綁定；回歸證明舊 controller 誤接受冒名來源，新 owner 拒絕。
- test-audit 確認 primary owner 是公開 tooling CLI：原生 pnpm 產生及評估雙文件 fixture，gh fixture 只提供外部 transport 資料，不實作 admission predicate。沒有刪測試或引入 test-only exports。
- 舊 namespace／ADR／accepted Proposal 沒有改寫；沒有新依賴或手寫 pnpm lock parser。

## 殘餘風險與 ownership

跨 shards 的 actionable 未緩解項目已在 Linear 依 root cause 合併或建立 follow-up：live platform activation／baseline／provider proof 保留在 shared operational issue；safe browser session、OAuth public activation、production observability 各回原 owner；完整 authenticated smoke gate 自動化另外追蹤，不把全部測試工程塞進本 Change。舊 sync retirement 只在成功切換後關閉，既有 Jest worker crash 不另造重複 bug。

Native SPDX submission 不保證 GitHub alerts／Dependabot updater 已端到端正常，亦不包含所有 package-manager environment dependencies；activation 時比較 root／Blueprint 與既有 environment graph，coverage 缺口不能被上傳成功掩蓋。新增 workspace 時需要對應 split submission 與 read-back。

Auto-merge 刻意只允許 manifest range 有 stable patch 變化、single signed bot commit 與小 diff；lock-only security updates／Dependabot rebased multi-commit／原生 regeneration 有任何其他差異時保持人工。這是可見且 fail-closed 的容量限制，不是漏洞修補已完成的宣稱。

Production 串行鎖會把 QA 等待算在內，急件先由 owner 處理目前等待 run，不繞過 gate。未知 DB compatibility／Git merge metadata conflict 都停止，Agent-first 不表示自動派工或自動獲得合併授權。

候選學習題目已記錄在 operational issue：pnpm environment/project 單雙文件模式、npm package-lock／hidden lockfile、version pin 與 scanner/dependency submission 的差異。這只是候選，不是排入 Cycle 的承諾；先前完整候選清單位置沒有得到可驗證結果，沒有另造一份重複名單。

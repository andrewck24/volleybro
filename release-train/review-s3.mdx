<ReviewDetails>

## Findings 與修正

- G2 接受後的 GitHub CodeQL 指出跨 job controller ref 可能導致不可信程式執行與 cache poisoning：移除 release cache，保留正常 merge 的 first-parent controller；在 candidate checkout 前封存可信 controller，各後續 jobs 只讀同 run 的 immutable artifact。沒有 suppression 或放寬授權。兩軸 delta review 達 fixed point，193 個 workflow tests 通過，最新 CodeQL／Verify／Vercel 全綠。

- Root review 發現以 main 的整份 package.json 覆寫 merge 結果會丟失 hotfix 依賴修補：改用 Git three-way merge，只正規化 root version；fixture 確認雙方變更保留。
- Spec review 發現 deployed-descendant 條件仍可能納入未發布 main history：檢查所有共同祖先是否屬於 deployed baseline，新增真實 CLI 舊失敗／新通過 regression。
- GitHub review 狀態以每位 reviewer 的最新決定為準，撤銷或 changes-requested 不沿用舊 approval；review 須綁 head SHA 與 collaborator 權限。
- Controller SHA 從可信 integration revision 取得並傳到後續 jobs，修補分支不能提供自己的 authorization／promote／rollback／finalize controller。
- failure summary 明確區分 publication 與同步結果；同步失敗時不自動重發或回退資料。

## 邊界與殘餘風險

Workflow-wide lock 刻意讓整個發布包含 QA 等待都串行，可能延後排隊中的 hotfix；此版不以額外 lock engine 換取平行度。需要加急時由 owner 先處理既有等待 run，不繞過 QA。

Git merge-file 對文字相鄰、不能乾淨合併的 package metadata 保守停止；不新增通用 JSON reconciliation engine。Main version／changelog 已經另外發布或未知時也停止，交 Agent 在乾淨 workspace 查明來源與雙方意圖，不能安全解決或需新決策才問開發者，不悄悄選一側。交接不啟動 unattended execution、不授予合併權限。

Production 基準缺少可信 source SHA、remote tag 不一致、reviewer 無適當權限、candidate QA 未完成，皆 fail closed。Semantic 上哪些 edits 屬於修補仍由 exact-SHA trusted review 判斷，Git history check 不冒充內容審查。

沒有 live production 操作、DB reset／搬移、credential 複製或權限擴大。自動 smoke 仍只證明首頁回應，完整 Google OAuth／登入後 session 驗證沒有在本批被虛構為已完成。
